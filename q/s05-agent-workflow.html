Agent／Agent 架构与工作流

什么是 Agent？它和 Workflow 有什么区别？

约 4 分钟
更新于 2026-10-13

题目

什么是 Agent？它和 Workflow 有什么区别？

面试口述回答

Agent 是一个围绕目标、根据环境反馈持续作决策的系统。它会选择工具、执行动作、读取结果，再决定下一步。Workflow 则预先规定主要步骤和分支，大模型可以作为其中一个处理环节。我会根据任务的不确定性选择：像字段提取、校验、入库适合固定流程，开放调研需要依据搜索结果不断调整，更适合 Agent。产品里通常把两者结合起来，稳定步骤流程化，探索部分交给模型。我的判断标准是任务是否更容易完成，以及成功率、成本和恢复能力是否改善。设计时还要把任务状态、完成条件和预算写清楚，整个循环才有可检查的进展。

详细知识笔记展开 / 收起

先解释 Agent 与 Workflow

Agent 是围绕目标，根据环境反馈选择行动、调用工具并持续推进任务的系统。 大模型通常承担决策：理解当前状态，选择下一步动作，读取动作结果，再决定继续、调整或结束。工具、记忆和运行环境让这些决定真正作用于任务。

Workflow 是预先定义主要步骤和分支的工作流。它可以包含大模型调用，例如“提取发票字段 → 检查金额与税号 → 生成报销记录”。其中模型负责理解文本，程序负责规定执行顺序。两者的核心区别在于下一步主要由既定流程决定，还是由模型根据当前观察决定。

Agent 的一次行动循环

以调研问题为例，Agent 先拆解缺失的信息，选择搜索词，读取搜索结果，再判断哪些假设已有证据、哪些还要补查；遇到冲突时调整搜索方向，证据足够后输出带依据的结论。这里每一轮的新信息都会影响下一轮行动。

一个清楚的状态可以包含：当前目标、用户约束、已完成步骤、证据、待解决问题以及剩余预算。环境反馈包括工具结果、操作错误和任务检查结果。把这些信息保存好，长任务就能在多次调用之间延续。

ReAct 怎样组织反馈驱动的检索

ReAct 将推理与行动交替组织：先分析已有信息与下一步需要，再调用搜索等工具，读取观察后更新计划。可以记成“推理 → 行动 → 观察 → 再决策”。例如先查出某位演员出演的电影，再根据查到的片名寻找导演，后一步的检索条件依赖前一步结果，因此需要分轮执行。

同一轮中彼此独立的检索可以并行，例如分别查两家公司的收入，再汇总比较。执行顺序由信息依赖决定：依赖前一步观察的动作随后执行，无依赖的动作可在预算内一起执行。ReAct 的重点是让新观察进入决策，让搜索方向、纠错和停止时机随证据更新。

怎样选择和组合

任务步骤稳定、约束明确、输入类型有限时，工作流便于测试和复现；开放调研、故障排查、资料不完整等任务，需要更灵活的探索，可以让 Agent 动态选择步骤。

实际产品常采用混合设计：资料检索和候选方案探索交给 Agent，格式转换、金额计算、文件保存等确定性环节交给固定流程。比如内容创作系统固定“大纲—分镜—素材—剪辑”的阶段，但允许模型根据缺失素材和用户修改意见调整局部执行。

选择时比较任务成功率、用户修改量、平均与尾部延迟、工具调用成本，并看失败后是否容易恢复。先建立简单基线，再把确实依赖环境反馈的决策交给模型，可以清楚看出增加自主性的收益。

怎样让循环有效结束

为任务定义完成条件，例如关键问题有依据、输出通过检查；同时给出预算和停机条件。工具失败后根据错误类型选择重试、替代工具或请求补充信息。记录每轮目标、动作和结果，方便回溯系统为什么走到当前状态。
