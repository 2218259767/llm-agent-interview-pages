模型后训练／RL 强化学习与偏好对齐

SFT 和 RL 有什么区别？应该怎样选择？

约 10 分钟
更新于 2026-10-13

题目

从学习原理和适用场景看，监督微调 SFT 与强化学习 RL 有什么区别？为什么常把它们组合使用？

面试口述回答

我会把 SFT 和 RL 的核心区别理解为：SFT 从高质量示范中学习怎样做，RL 通过尝试和反馈学习怎样做更容易达到目标。

SFT 更像行为模仿。我们把好的回答、推理过程或工具轨迹交给模型，让它进入一个自然、可用、服从指令的行为分布。RL 更像结果导向的策略优化：模型自己 rollout、尝试不同路径，再根据回报提高有效行为的概率。

我觉得其中一个很重要的区别是，SFT 更偏行为范式的注入，RL 更偏潜在能力的筛选、强化和策略化。模型可能原本偶尔能找到一条好的路径，RL 的价值是把这种低概率的成功方式放大、稳定下来，让它更经常在合适的情境下做出有效决策。

这个区别在 Agent 上很直观：SFT 可以教会模型怎样调用搜索工具、读材料和写引用；RL 则可以进一步优化什么时候继续搜、什么时候改查询、什么时候停止，最终兼顾任务质量和执行成本。

所以我会根据训练信号选方法：高质量示范丰富、期待行为明确，先把 SFT 做好；结果容易评价、存在多种值得探索的策略，再考虑 RL。两种条件都具备时，通常先 SFT 建立可用起点，再 RL 优化目标相关的决策。我更看重这两个阶段各自解决了什么问题，以及最终能否提升真实任务的完成质量。

详细知识笔记展开 / 收起

1. 学习范式：行为模仿与结果导向的策略改进

SFT 是从示范里学怎么做，RL 是从结果和反馈里学怎样做更值得。这个区别贯穿了两者的数据来源、训练目标和适合解决的问题。

SFT 的出发点是：“这里有一些高质量示范，你学着这样做。”训练者把期待的行为直接展示给模型，模型学习在相似条件下生成这样的回答或行动。示范可以包含最终答案、推理过程、多轮交互或完整工具调用轨迹，因此 SFT 既能教输出形式，也能教解题方法和任务流程。

RL 的出发点是：“你自己去尝试，我根据结果告诉你哪些行为更值得重复。”模型产生回答或行动轨迹，环境、验证器或奖励模型提供反馈，训练再提高高回报行为的生成概率。这里需要回答的是：面对同一个目标，哪种决策路径更容易成功？

从学习范式看，SFT 更偏高质量行为模仿，RL 更偏反馈驱动的策略优化。前者通过示范明确“希望你这样做”，后者通过评价引导“这样做更有用”。

2. 训练目标如何体现这种差别

SFT 常用目标是提高示范回答的条件概率：

LSFT=−E(x,y)∼D∑tlog⁡πθ(yt∣x,y<t).\mathcal L_{\mathrm{SFT}}=-\mathbb E_{(x,y)\sim D}\sum_t\log\pi_\theta(y_t\mid x,y_{<t}).LSFT​=−E(x,y)∼D​t∑​logπθ​(yt​∣x,y<t​).

DDD 是示范数据集，xxx 是输入，yyy 是目标回答。训练时以示范中的已有前缀预测下一个目标 token，监督信号来自“参考轨迹在这里做了什么”。因此，示范的质量、覆盖范围和推理方法，会直接影响模型学到的行为分布。

RL 的目标可以写成最大化策略产生轨迹的期望回报：

J(θ)=Eτ∼πθ[R(τ)].J(\theta)=\mathbb E_{\tau\sim\pi_\theta}[R(\tau)].J(θ)=Eτ∼πθ​​[R(τ)].

τ\tauτ 表示完整回答或交互轨迹，R(τ)R(\tau)R(τ) 表示奖励。一次 rollout 就是让模型按当前策略走出一条这样的轨迹。奖励既可以来自最终结果，也可以包含过程质量、工具成本等评价；策略优化算法再把反馈转化为参数更新。

比如同一道题存在三种有效解法，SFT 可以学习数据里展示的一种或多种解法；RL 可以采样不同路径，再围绕正确率、调用成本或完成时间调整它们的概率。两者的区别体现在训练信号怎样定义“好”，以及模型怎样接触到这些好的行为。

3. 示范塑造行为分布，反馈决定优化方向

SFT 擅长把高质量示范中的行为蒸馏进模型，让模型快速进入一个可用、自然、服从指令的分布。我们希望助手怎样理解要求、怎样组织回答、怎样按格式调用工具，就把相应范例交给它学习。

RL 则进一步回答：在很多难以给出标准示范、或者现有示范仍有改进空间的任务里，什么样的行为更能带来最终成功？这时可以通过目标和反馈给出方向，让模型在尝试中改进。

因此，可以把常见的两阶段流程理解为：SFT 塑造初始行为分布，RL 在这个分布上进行面向目标的重新加权。例如，SFT 示范中的搜索 Agent 每次都会搜索三轮；真实任务有的查一次就足够，有的需要换关键词和交叉验证。RL 可以通过任务成功与调用成本的反馈，学会根据当前信息状态决定继续、改查或停止。

“重新加权”说的是策略概率会怎样变化：原本经常出现但收益低的行为减少，原本偶尔出现但收益高的行为更常被采用。它把“模仿一条已有路径”推进到“根据目标选择合适路径”。

4. 行为范式的注入，与潜在能力的筛选、强化和策略化

原笔记里一个很有价值的理解是：SFT 更像告诉模型应该成为什么样子，RL 更像让模型通过探索发现自己怎样能做得更好。

SFT 主要依赖外部示范，把知识的表达方式、解题方法或交互范式直接教给模型。例如，一条优质示范可以展示“先拆分问题，再逐项检索，最后用证据回答”的完整流程。模型由此获得可以模仿的行为模板。

对于已经具有相关基础能力的模型，RL 的 rollout 可能暴露出一些原本存在、但出现概率很低的高质量策略。训练通过反馈把这些策略放大、稳定化，使“多试几次偶尔能做对”逐步变成“更经常主动选择有效做法”。

这种潜力可能体现在：发现检索证据不足时改写查询；遇到工具失败时换路线；回答前主动核对关键事实；在较难的问题上投入更多推理步骤。学习的价值在于让这些有效行为进入模型日常使用的策略，而不仅是偶然出现在某次采样里。

所以，SFT 更偏知识与行为模板的注入，RL 更偏潜在能力的筛选、强化和策略化。这里的“策略化”尤其重要：模型要学会在什么状态下采用什么行为，让有效动作组合成一条更容易成功的路径。这一视角可以继续展开到Agent 中强化学习的作用。

5. 两者适合怎样的任务结构

当高质量示范容易获得，而且能够清楚表达期待行为时，SFT 很直接。例如指令跟随、风格对齐、格式化输出、常见领域问答、基础工具调用，都可以通过“输入—理想输出”或示范轨迹给出明确监督。对于答案形式和处理流程较固定的任务，做好示范质量与覆盖，往往就能显著改善效果。

SFT 同样可以学习多步推理和多轮任务；只要能提供足够好的过程示范，模型就能学习其中的方法。因此选型时要看的是“好行为是否容易示范、示范能否覆盖真实场景”。

当逐步示范难写，但结果较容易评价，而且存在值得探索的多种策略时，RL 更有吸引力。例如可验证的数学推理、具有明确成功条件的 Agent 任务、长链路工具使用、搜索规划与多轮决策。训练者可以定义目标，让模型探索怎样达到它。

这里的任务结构决定了反馈的价值：如果不同路径带来的成功率、成本或时延差别很大，策略优化就有明确空间。例如研究型 Agent 可以直接回答，也可以检索、比较来源、继续追问；奖励需要让模型学会在信息质量和执行代价之间做出合适选择。

6. 用搜索 Agent 说明“能力可用”和“决策更好”

原笔记把常见分工概括成：SFT 更多是在建立能力的可用接口，RL 更多是在提升能力的利用效率和决策质量。放到一个具体任务里，这个表述会更清楚。

假设任务是查询某项技术的最新进展，并给出有依据的回答。SFT 可以用完整示范教会模型：理解用户的问题、构造合法搜索参数、读取返回材料、提取相关证据、附上引用并组织回答。这一步让已有语言和知识能力通过工具接口参与任务。

接下来，同一个 Agent 可能面对不同状态：

  • 第一轮结果已经包含清楚的一手证据，此时应整理答案并停止。
  • 检索结果相关性低，此时应调整关键词或拆分子问题。
  • 不同来源存在冲突，此时应继续查找原始材料并核对时间和版本。
  • 某个工具调用失败，此时应判断重试、换工具或改走另一条路径。

这些选择关系到整条轨迹能否完成目标。RL 可以结合答案质量、证据质量、任务成功和调用成本，强化有效决策。奖励只在任务结束时给出时，训练还需要解决信用分配：整条路径的回报怎样影响其中各步行动的学习。

因此，“SFT 先让模型会，RL 再让模型更会赢”适合作为对常见流程的直观记忆：先让模型能够进入有效解题流程，再提高它选择高价值路径的概率。真正展开时，要说明具体学会了什么接口、优化了哪些决策，以及目标如何评价。

7. 应该怎样选择，为什么经常先 SFT 再 RL

我会先判断三件事：当前缺的是哪种行为、可靠信号在哪里、训练代价是否值得。

  1. 已有清楚的好示范，模型主要欠缺规范行为或任务方法：先做好 SFT。例如输出格式不稳定、工具参数经常错误，或者不会按领域要求组织回答，可以直接通过高质量示范纠正。
  2. 模型已经能够完成基础动作，但路径选择影响最终表现：如果任务成败可以可靠评价，就考虑 RL。例如检索 Agent 会调用所有工具，却经常反复搜索或过早结束，训练目标应落到成功率、证据质量和成本之间的选择。
  3. 示范和反馈都具备：先用 SFT 建立可控、稳定、可用的行为起点，再让 RL 围绕特定目标改进。SFT 缩小无效探索范围，RL 利用真实尝试发现示范之外更有效的做法。InstructGPT 的流程就是先从示范进行监督训练，再利用人类偏好反馈优化策略。
  4. 最终质量主要依赖主观判断，评价还不可靠：优先积累可靠示范与评价数据。反馈决定 RL 的优化方向，因此需要先把“什么叫完成得好”转化成稳定的评价信号，再投入大量 rollout。

成本也要一起考虑：SFT 的投入主要是示范数据制作和训练；在线 RL 还需要持续生成轨迹、调用环境或工具、计算奖励，并处理更长的反馈链路。选择时应结合具体任务的质量提升和新增训练成本。

两者是围绕数据、起点和目标形成的分工。常见工程流程采用 SFT → RL；当基座已具备足够的探索能力、任务又有可靠反馈时，也可以直接从基座开展 RL，例如 DeepSeek-R1-Zero。有些格式与风格任务则通过 SFT 就可以达到应用目标。
