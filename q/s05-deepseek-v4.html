模型家族／DeepSeek 系列

请介绍一下 DeepSeek-V4，它有哪些主要改进？

约 6 分钟
更新于 2026-10-13

题目

请介绍一下 DeepSeek-V4，它有哪些主要改进？

面试口述回答

DeepSeek-V4 的核心是高效百万 token 上下文，以及围绕长任务构建的后训练体系。架构上，它延续 MoE，引入 CSA 和 HCA 压缩注意力，配合局部窗口降低长上下文开销，再用 mHC 和 Muon 改善模型表达与训练。后训练先用 SFT 和 GRPO 训练各领域专家，再通过多教师 OPD 把能力整合到统一模型。Agent 方面，它改进 DSML 工具表示，保留工具场景的跨轮思考状态，并用 Quick Instruction 复用缓存完成辅助决策。我会把它理解为一次系统性的能力升级：长上下文成本、状态连续性、能力整合和训练基础设施一起为长程任务服务。

详细知识笔记展开 / 收起

先抓住模型定位

DeepSeek-V4 是面向高效百万 token 上下文的 MoE 模型系列。官方 V4 报告介绍了 Pro 和 Flash 两个版本：Pro 总参数约 1.6T、每 token 激活约 49B；Flash 总参数约 284B、激活约 13B，均支持 1M 上下文。

它的主线可以概括为：降低长上下文成本，支持更长的推理和 Agent 任务，再通过后训练整合多领域能力。 这里讨论的是 V4 报告所述版本，系列参数按官方模型卡核对。

架构：压缩注意力、增强残差与优化器

V4 延续 DeepSeekMoE 和多 token 预测，主要加入三项设计。

  • CSA（Compressed Sparse Attention）：沿序列维度压缩 KV，再用索引器选取相关压缩块参与注意力。它同时减少缓存长度和实际参与计算的条目。
  • HCA（Heavily Compressed Attention）：采用更高压缩比例，在压缩后的条目上做稠密注意力。CSA、HCA 与局部滑动窗口配合，兼顾远程信息和近邻细节。
  • mHC 与 Muon：mHC 扩展残差流并约束混合映射，改善跨层传播稳定性；Muon 用于大部分适用参数的优化，配合归一化等训练设计控制数值稳定性。

报告在 1M 上下文的估算口径下给出：V4-Pro 的单 token 推理 FLOPs 约为 V3.2 的 27%，KV Cache 约为 10%。这是理解其设计动机的代表性结果：长任务中能保留更多历史，推理与状态管理有更大操作空间。

预训练与后训练怎样衔接

预训练使用超过 32T token，并逐步增加上下文长度，让压缩注意力与长序列共同训练。

后训练先按数学、代码、Agent、指令遵循等领域训练专家：先做领域 SFT，再用 GRPO 和对应奖励优化。最后让统一学生在自己生成的轨迹上学习多个专家教师的输出分布，通过完整词表的反向 KL 做 On-Policy Distillation。这把领域内优化和跨领域能力整合分成两个阶段，OPD 接替了 V3.2 的混合 RL 合并阶段。具体蒸馏目标见 OPD 原理。

难以用规则验证的任务采用 rubric 引导的生成式奖励模型（GRM），通过评价过程与轨迹判断质量，并对评价能力本身进行 RL 优化。不同推理强度还使用不同训练配置和输出格式，让模型适应快速响应和深入推理的预算。

Agentic 能力怎样增强

长上下文提供状态容量，工具协议与训练使这些状态得到有效利用。

V4 采用 DSML 特殊标记和 XML 风格的工具表示，减少结构化参数的转义问题。工具调用场景中保留完整的跨轮推理历史，包括新用户消息后的相关历史，使任务状态可以持续累积；普通对话采用适合简洁上下文的管理方式。

Quick Instruction 使用专用 token 触发搜索判断、查询生成、领域判断等辅助任务，复用主模型已有 KV Cache，减少独立辅助模型带来的重复预填充。多轮搜索则根据环境反馈继续检索、核对和综合，实际使用时共同衡量任务效果、工具成本与延迟。

在自己的 Agent 中怎样接入工具协议

使用官方 API 时，通过 tools 声明工具，读取 tool_calls，执行后以 tool 消息和对应调用标识返回结果。应用保留服务要求的完整助手消息与思考字段。模型底层使用的 DSML 序列格式由服务端适配。

自部署权重时，按官方提供的消息编码与解析实现衔接推理服务，保持训练模板、工具角色和输出解析一致。这样能够把“模型如何表示工具调用”与“应用怎样调用工具”两层正确接上。

支撑训练与部署的系统设计

完整词表 OPD 需要高效调度教师：缓存隐藏状态、按教师组织小批次并重建输出分布，可以降低显存和搬运压力。长轨迹 rollout 使用可恢复的日志与服务，沙盒记录环境动作，支持中断续接。再结合专家并行、低精度与确定性计算，形成支撑规模化 Agent 训练的基础设施。

面试时可以把这些设计串起来：架构负责让长任务成本可承受，协议与状态管理负责可靠交互，专家训练与 OPD 负责能力整合，基础设施负责把整条流程运行到足够规模。
