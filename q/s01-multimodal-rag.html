RAG 检索增强生成／多模态 RAG

知识库里既有文字又有商品细节图，RAG 应该怎样利用图片？

约 3 分钟
更新于 2026-10-13

题目

知识库里既有文字又有商品细节图，RAG 应该怎样利用图片？

面试口述回答

我会按索引、检索和生成三个环节设计。索引上同时保留商品文本和图片，并用父子结构把每张细节图关联到商品主体。检索时，文字问题可以同时走文本检索和 CLIP 文搜图，用户上传图片则走图搜图；多路结果按商品去重、融合并重排。生成时，把关键图片或局部裁剪与对应商品资料成组交给多模态模型。图片 token 成本较高，所以只给最相关的候选保留原图，其余提供简短文字。这样既能使用视觉细节，又能控制上下文和推理成本。

详细知识笔记展开 / 收起

先明确图片承担的任务

商品标题和规格适合回答型号、价格、尺寸等问题；图片适合提供外观、纹理和局部结构信息。多模态 RAG 要把这两类证据关联起来，再根据用户问题决定检索和展示哪些内容。

索引：文本与图片建立关联

文本可保留关键词索引和语义向量；图片可生成 Caption/OCR 文本索引，同时保存原图、视觉向量和元数据。对于一件商品的主图、侧面图和细节图，采用父子结构：

  • 父节点：商品 ID、标题、规格、价格与版本等信息。
  • 子节点：每张图或关键区域，附所属商品、部位、视角和图片地址。

检索命中鞋底细节图时，可以回到对应商品，取出该商品的规格与其他必要证据。

检索：根据输入类型组合路径

  1. 文本查询：文本编码器检索商品文本；配套的 CLIP 文本塔还可查询 CLIP 图像向量，找到符合外观描述的图片。
  2. 图片查询：使用同一视觉编码器得到查询图片向量，检索相似商品图。
  3. 图文组合查询：例如“找类似这双鞋、但颜色为蓝色”，用图片召回相似款，再结合蓝色属性过滤或重排；也可使用专门训练的组合查询模型。

各索引内部使用匹配的编码器和向量空间；多路结果在文档或商品层通过排名融合、去重与重排合并。重排同时考虑视觉相关性、文字属性和证据质量。

生成：让图文证据一一对应

把选中的原图或裁剪区域交给支持图像输入的模型，旁边附商品 ID、标题和相关规格，组织为“商品 A 的图片与信息”“商品 B 的图片与信息”。模型据此比较图片中的可见特征和文字中的规格信息。

多图会增加视觉 token、首 token 延迟与显存开销，因此先重排，只给关键对象提供图片；其他候选保留简短元数据。涉及小字或纹理时，优先提高关键区域的清晰度，而整体无关区域可以压缩。

怎样检查整条链路？

分别检查图片是否召回、商品与图是否对应、关键局部是否看清、回答是否使用了正确证据。这样能判断问题发生在索引、检索、视觉读取还是生成环节。
