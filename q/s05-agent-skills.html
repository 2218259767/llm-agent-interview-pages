Agent／MCP、Skills 与工具调用

Agent Skills 是什么？它和 MCP 有什么关系？

约 4 分钟
更新于 2026-10-13

题目

Agent Skills 是什么？它和 MCP 有什么关系？

面试口述回答

Agent Skill 可以理解为可复用的任务操作包，它把一类工作的步骤、输入输出要求、参考资料和检查方法整理在一起。比如分镜规划 Skill，会告诉 Agent 怎样拆故事、维护角色设定、输出镜头表并检查一致性。MCP 负责统一连接外部工具和上下文服务，Skill 负责组织怎样用这些能力完成任务；模型再通过具体工具调用执行每一步。我会让 Skill 按需加载，入口简洁，长参考和模板分开放。设计的重点是触发条件清楚、失败可恢复、结果可评估，让每个 Skill 都能独立维护并验证效果。

详细知识笔记展开 / 收起

Skill 封装什么

Skill 把完成某类任务的操作知识、步骤和资源组织成可复用的能力包。例如“把故事转换成分镜”需要说明如何拆分场景、输出哪些字段、怎样保持人物设定，以及如何检查镜头顺序。Agent 匹配到任务后加载这些说明，按流程使用工具完成工作。

在 Agent Skills 开放规范中，入口是带名称、适用描述和正文的 SKILL.md。正文描述操作流程，附带资源可以包括参考资料、模板和可执行脚本。输入输出约束主要由说明和实际工具接口共同表达。

为什么采用按需加载

一个 Agent 可能具备报告制作、检索、图片处理等多种能力。发现阶段先读取 Skill 的名称和适用描述；任务匹配时加载详细说明；执行到相关步骤时再读取参考文件和资源。这样每个能力包能独立维护，当前上下文也更集中。

例如分镜 Skill 的入口只保留拆解步骤、字段定义与检查项，把完整镜头示例放到参考文件，把固定导出格式放到模板里。常用规则容易找到，长材料在需要时展开。

和 MCP、工具调用怎样配合

组件 主要负责什么 创作任务中的例子
Skill 如何完成一类任务，采用哪些步骤和检查标准 故事拆解、角色设定、分镜规划的方法
MCP 应用以统一协议连接工具与上下文服务 接入素材库、项目文件和剪辑服务
工具调用 发起一次具体操作并接收结果 按角色名检索素材、生成某个镜头

三者可以协同：Agent 加载分镜 Skill，按其中步骤通过 MCP 连接素材库，调用检索工具，最后依据 Skill 的检查表验证输出。关于协议本身，可接着复习 MCP 的概念与 Function Calling。

一个好 Skill 应该写清什么

首先说明触发场景及必要输入；然后给出步骤、分支条件和输出格式；再说明失败后的恢复方式，例如缺素材时先补齐角色参考，再继续生成。最后列出可观察的验收条件，例如每个镜头都有时长、动作、台词和角色标识。

工具的执行权限由宿主环境控制。版本更新后，用固定代表任务检查触发是否准确、流程是否完整、输出质量以及额外成本。对于分镜任务，可以记录字段完整率、角色设定一致性和用户返工量，让 Skill 的改进有实际依据。
