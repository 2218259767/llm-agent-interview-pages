Agent／MCP、Skills 与工具调用

如何让一个 Agent 接入 MCP 工具？请说明完整调用流程。

追问约 4 分钟
更新于 2026-10-13
这道题接续MCP 是什么？它和 Function Calling 有什么关系？

题目

如何让一个 Agent 接入 MCP 工具？请说明完整调用流程。

面试口述回答

让 Agent 接入 MCP，我会从服务端和应用端两边说明。服务端先把业务能力包装成工具，定义名称、描述、输入 schema 和结果结构，再通过 stdio 或 Streamable HTTP 提供服务。Agent 侧由 MCP Client 发现能力、读取工具列表，把合适的定义交给模型。模型生成工具名和参数后，Host 校验授权与参数，转成 tools/call 请求发给 Server；结果返回后再进入模型上下文，继续完成任务。整个链路还需要统一超时、错误处理、幂等和日志。这样工具的业务实现与 Agent 的规划逻辑就有了清晰的分工。

详细知识笔记展开 / 收起

场景与整体结构

假设 Agent 需要查询企业知识库，可以把查询能力封装为 MCP Server；Agent 所在的 Host 通过 MCP Client 连接它。服务端维护查询逻辑和业务数据访问，应用侧维护工具选择、执行控制和模型上下文。

本题从口述架构说明接入过程。MCP 的概念可先看：MCP 是什么？

服务端准备什么？

  1. 定义工具名称和描述，让模型理解适用任务。
  2. 用输入 schema 描述参数，例如查询语句、返回条数及可选过滤条件。
  3. 实现业务查询，进行参数与权限校验，约定成功结果和错误结果结构。
  4. 选择运行方式：本地进程使用 stdio，远程服务使用 Streamable HTTP。
  5. 按需要提供资源与提示模板，例如知识库目录、查询提示。

工具描述要有明确的输入、输出和作用范围；结构化结果中带上稳定 ID、来源和必要字段，方便 Host 继续处理。

Agent 侧的一次完整调用

发现能力。 Client 获取服务端版本和能力，再通过 tools/list 获取工具 schema。Host 将需要的工具注册到模型可用列表。

模型决策。 模型根据用户问题生成工具调用，例如选择知识库搜索并给出查询参数。

执行请求。 Host 检查参数、用户授权与预算，由 Client 发起 tools/call；Server 执行业务逻辑后返回结果。

回传并继续。 Host 把结果与对应调用 ID 关联，加入模型上下文；模型据此继续检索、调用其他工具或组织最终回答。

需要设计好的运行细节

  • 超时与错误分类：区分参数错误、权限错误、网络暂时失败和业务无结果。
  • 重试与幂等：查询通常可重试；有写入效果的工具使用业务幂等键控制重复执行。
  • 权限与凭证：按用户和工具约束访问范围，凭证由相应服务或受控代理管理。
  • 结果与上下文：保留必要来源，控制返回大小，明确工具结果是业务数据。
  • 可观测性：关联请求 ID，记录工具耗时、结果状态和错误位置。

2026-07-28 协议使用 server/discover 与每次请求的元数据进行能力、版本处理；若维护采用 2025-11-25 规范的系统，则其接入生命周期使用 initialize。接入时以部署的协议版本组织流程。
