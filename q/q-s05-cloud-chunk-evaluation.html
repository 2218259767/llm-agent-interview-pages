题目

RAG 应该怎样分块，如何单独评估分块质量？

SPEAK WITH CLARITY · 面试表达

面试口述回答

我会先确定分块到底服务什么检索任务。小块容易命中细节，大块能保留条件和指代，所以没有一个固定长度适合所有文档。第一版通常先利用标题、段落和句子，再按 token 预算聚合，表格和代码单独处理。评估时我会标注问题对应的证据跨度，检查有没有切断事实，同时观察重复率和索引成本。最关键的是下游对照要固定检索 token 预算，否则大块只是因为给模型看了更多文本而占便宜。Embedding 或大模型分块可以作为候选，但只有证据召回和最终正确性提升，且成本值得，才采用。

详细知识笔记展开 / 收起

分块是在检索粒度、证据完整性和成本之间做选择。固定 token 窗口简单可控，但可能把事实关系切开；按标题、段落和句子聚合通常能利用文档结构；Embedding 相似度或模型辅助切分能够考虑语义，但会增加索引开销，效果仍需实测，不能预先称为“最完整”或“最好”。NLTK 分句只是其中一个边界检测组件，不等于完整的 token 预算分块方案。

小块可能便于匹配局部事实，却丢掉指代、单位或适用条件；大块提供更多上下文，却可能稀释检索信号，并使无关信息占用生成预算。Overlap 有助于保留边界信息，但会增加索引体积、重复召回和重复计分。固定长度切分仍要遍历输入，不能把整篇处理的复杂度称为常数时间。

独立评估可以标注一组问题及其最小支持证据跨度，检查关键事实是否完整落在可被召回的块或相邻块组合中，是否保留标题、时间、对象和单位；同时测 token 长度分布、超长率、重复率与索引成本。不存在唯一“完美语义边界”，因此边界 F1 只能是人工定义协议下的诊断指标。

下游评估保持文档、查询、Embedding、检索器和生成模型不变，仅改变分块；在相同检索 token 预算下比较证据召回、回答正确性和引用支持率。只固定 top-k 会使大块方案获得更多 token，造成不公平比较。可再补固定 top-k 的实验，区分块数预算与 token 预算。

对表格、代码和列表，优先保留行列标题或语法结构。跨块事实可采用父子块：小块用于定位，再恢复有限的父段上下文。最终选型依据目标数据的失败案例，而不是技术复杂度。
