什么是 MoE 混合专家模型？它主要解决什么问题？

约 3 分钟
更新于 2026-10-13

题目

什么是 MoE 混合专家模型？它主要解决什么问题？

面试口述回答

MoE 是混合专家模型，通常把 Transformer 中的一个 FFN 扩展成多个专家，再用路由器为每个 token 选择少量专家计算，最后把结果加权合并。

它主要解决参数容量和计算成本一起增长的问题。Dense 模型扩大后，每个 token 都要经过更多参数；MoE 可以保存很多专家，却只激活其中几个，所以能用较小的单 token 计算承载更大的模型容量。

理解 MoE 时要分清总参数和激活参数：总参数影响权重存储，激活参数影响每 token 算量；多卡之间还要承担路由和通信。我觉得它的特点就是，用模型和系统协作的复杂度，换取更好的参数容量与计算效率。

详细知识笔记展开 / 收起

1. MoE 的组成

MoE（Mixture of Experts，混合专家）在模型中设置多个专家网络，由路由器为每个 token 选择少量专家参与计算。在语言模型里，常见做法是把部分 Transformer 层的一个 FFN 替换成多个 FFN 专家。

路由器读取 token 的隐藏状态，计算各专家分数；选中的专家加工这个 token，最后将输出加权合并。可以把它理解成“调度员分配任务给一组计算单元”。专家的分工由训练形成，可能围绕语法、词元类型或更抽象的特征出现偏好。

2. 为什么需要稀疏激活？

Dense 模型处理一个 token 时，通常会经过该层全部参数。扩大 Dense 模型会同时增加参数容量和每 token 计算量。

MoE 让总专家数较多、每次选中的专家数较少。因此能在增加参数容量的同时，把每 token 的专家计算维持在较小规模。这是 MoE 最核心的价值：用稀疏激活，在给定计算预算下容纳更多参数。

3. 总参数与激活参数怎样理解？

设模型的公共部分有 PsharedP_{shared}Pshared​ 个参数，共有 EEE 个等规模路由专家，每个专家参数量为 PeP_ePe​，每个 token 激活 kkk 个，则粗略为

Ptotal=Pshared+EPe,Pactive=Pshared+kPe.P_{total}=P_{shared}+EP_e,\qquad P_{active}=P_{shared}+kP_e.Ptotal​=Pshared​+EPe​,Pactive​=Pshared​+kPe​.

总参数关系到权重存储容量，激活参数反映单 token 实际经过的参数规模。例如 Mixtral 8×7B 的总参数约 47B，每 token 选择 2 个专家，激活参数约 13B；注意力等公共模块仍参与计算。

4. 付出的代价

保存全部专家需要较大的存储容量，多卡部署通常把专家分布到不同设备，Token 的派发和收回会增加通信。训练还需要管理专家负载，给各专家足够的学习机会。

因此，MoE 选型通常同时看三个量：总参数决定如何装下模型，激活计算决定主要算量，路由与通信决定设备能否高效协作。在硬件互联和负载适合时，MoE 能很好地发挥计算效率优势。
