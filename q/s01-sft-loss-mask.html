多轮对话 SFT 的 Loss 是怎么计算的？

约 4 分钟
更新于 2026-10-13

题目

在多轮对话 SFT 中，怎样计算 Loss？为什么要设置 Loss Mask，拼接多个样本时又怎样处理 Attention Mask？

面试口述回答

多轮对话 SFT 仍然是自回归的下一 token 预测。常见做法是把完整对话作为上下文，只对助手回答计算交叉熵；用户、系统提示和 padding 的 label 设为忽略值。这样模型能利用问题和历史对话，训练目标集中在怎样回答上。这里有两个不同的 Mask：Loss Mask 决定哪些 token 计入损失，Attention Mask 决定哪些 token 可以互相看到。如果做 Sample Packing，把多条对话拼在一起，还需要处理样本边界的注意力隔离。我会抽样检查角色、label、结束符和移位是否对齐，确保训练数据真的对应预期的回答任务。

详细知识笔记展开 / 收起

先把对话整理成模型能读取的序列

按照模型的对话模板，把 system、user、assistant 的角色标记与文本拼成序列。模型采用自回归训练：看到当前位置之前的内容，预测下一个 token。多轮对话中，前面的用户提问与助手回答共同构成后续回答的上下文。

只让目标回答贡献训练损失

常见的 assistant-only SFT 只监督助手回答。令 mtm_tmt​ 表示当前位置是否属于需要学习的助手输出，则：

LSFT=−1∑tmt∑tmtlog⁡pθ(yt∣y<t).\mathcal L_{\mathrm{SFT}}=-\frac{1}{\sum_t m_t}\sum_t m_t\log p_\theta(y_t\mid y_{<t}).LSFT​=−∑t​mt​1​t∑​mt​logpθ​(yt​∣y<t​).

mt=1m_t=1mt​=1 的 token 贡献交叉熵损失；用户输入、系统提示和 padding 的 mt=0m_t=0mt​=0。在常见训练接口中，这些位置的 label 被设为 -100，由损失函数忽略。模型仍然会读取这些上下文，并通过它们影响回答。

例如一条对话包含“用户问题一—助手回答一—用户问题二—助手回答二”，可以监督两轮助手回答，也可以只监督最后一轮；选择取决于数据质量和训练目标。助手结束标记通常也需要监督，让模型学会正确结束回复。使用训练框架时，要核对标签移位由哪一层完成，使“当前隐藏状态预测下一个 token”对齐。

Loss Mask 与 Attention Mask 各管什么

Loss Mask 决定哪些位置参与学习目标；Attention Mask 决定哪些位置之间可以读取信息。 助手回答需要读取用户问题，即使用户部分没有直接损失。

为减少 padding，可以把多个短样本装进同一训练序列，即 Sample Packing。若希望各条对话保持独立，就给每条样本使用内部因果注意力，并隔开样本边界，防止后一条对话读取前一条无关对话。变长注意力实现还可以通过序列长度信息表达边界。相应地，检查位置编号、结束符和有效 token 数是否与样本边界一致。

如何检查训练数据

抽一条真实样本，把角色、文本和 label 对齐展示出来，确认助手有效 token 被监督，用户与 padding 被忽略，截断后仍有完整可学习回答。对于多轮和 packing 样本，再分别检查轮次选择和跨样本隔离。这比仅观察总 Loss 更容易定位数据处理错误。
