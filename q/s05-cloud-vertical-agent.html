Agent／Agent 架构与工作流

通用 Agent 越来越强，垂直 Agent 还有什么价值？

约 5 分钟
更新于 2026-10-13

题目

通用 Agent 越来越强，垂直 Agent 还有什么价值？

面试口述回答

通用 Agent 的优势是任务覆盖面，垂直 Agent 的价值是把某类任务做深。我会从四方面看它的核心能力：第一是明确成功标准和评测，比如研究任务里的覆盖率、事实支持和引用质量；第二是领域数据与真实反馈，能持续积累失败案例并改进；第三是嵌入业务流程，包括权限、人工审核和最终交付；第四是在质量要求下控制时延与成本。以 Deep Research 为例，检索规划、证据保留和引用验证都可以围绕研究任务优化。我的判断是，通用平台会提供越来越成熟的底座，垂直系统则负责把这些能力变成某个业务里可验收、可持续使用的结果。

详细知识笔记展开 / 收起

先说明通用 Agent 与垂直 Agent

通用 Agent 面向较广的任务范围，通过模型、工具和运行系统处理搜索、编程、文档及跨应用操作。垂直 Agent 围绕某类任务或某个领域深入设计，例如研究报告、客户服务、企业运维或合同审查。

两者可以共享模型、工具协议和运行时。垂直系统的重点在于把领域里的“怎样算做好”变成明确目标，再围绕这个目标组织数据、流程和评估。

垂直系统的价值可以从四方面回答

方面 具体要做好什么 以研究 Agent 为例
成功标准与评测 明确用户真正关心的结果，把失败分成可改进的类型 主题覆盖、证据支持、引用完整、报告可用性
领域数据与反馈 积累领域材料、真实失败案例、人工纠偏和验收记录 某行业术语、可靠数据源、常见口径差异
业务流程集成 接入实际工作步骤、权限、审核与交付系统 研究需求拆解、内部资料检索、专家复核、报告归档
成本与服务质量 在可接受的预算和等待时间内持续完成任务 搜索预算、模型路由、缓存、重试、人工复核成本

这些能力相互促进：真实使用产生失败案例，失败案例进入评测，评测指导检索、上下文和工具流程的改进，改进后再回到业务中验证。

Deep Research 可以在哪些地方做得更深？

研究任务往往需要连续搜索、多来源比较、保存证据，再形成可引用的结论。围绕这个流程可以做定向优化：

  • 把研究目标拆成可验证的覆盖清单，决定下一步还需要查什么。
  • 在多轮搜索中保留关键证据与未解决的问题，控制上下文增长。
  • 建立陈述到原文片段的映射，检查引用支持、时间和统计口径。
  • 用实际研究任务构成评测集，把漏查、误读、无依据推断、成本超支等问题分开分析。

例如“分析某行业的主要增长驱动”需要覆盖市场规模、客户需求、竞争变化与风险。系统可以围绕这些维度规划检索和验收，交付前检查每项结论的依据。这样，领域知识被落实到了可以观察的任务结果上。

怎样回答“你的系统性能更强吗”？

先明确任务集合、可使用的数据和工具、质量要求与预算，再做比较。研究类系统可以同时看主题覆盖、事实支持、引用质量、时延、费用以及人工修改时间。

分析结果时指出优势来自哪一环：领域语料提升了召回，任务清单减少了漏项，证据检查减少了错误引用，或固定流程降低了执行成本。面试中能够把结果连接到具体机制，会比只给一个总分更有说服力。

通用能力继续提高后，分工会怎样变化？

我的判断是，通用平台会继续承接模型调用、通用工具、运行时和任务协作，垂直应用把更多精力放到领域目标、业务数据、工作流程和验收标准上。

只依靠固定提示词与简单界面的应用，需要随着通用能力提升寻找更具体的价值。拥有真实业务反馈和深度集成的系统，可以直接吸收更强的通用能力，同时继续优化自己负责的任务。持续竞争力体现在用户最终交付的质量、成本和工作效率上。
