更新于 2026-10-13

题目

OpenClaw 是什么？请介绍它的整体架构和关键设计。

面试口述回答

OpenClaw 是一个可以自行部署、常驻运行的 AI 助手平台。它的核心是 Gateway，把飞书等消息入口、会话路由、Agent 运行时、记忆、工具和自动化接在一起。一条消息进来后，系统先找到对应 Agent，准备工作区规则和相关记忆，再运行模型与工具循环，最后把结果返回并保存状态。它很有特点的一点是文件化工作区：规则、用户偏好、日记和长期记忆可以直接查看和维护，执行时再按需检索。不同 Agent 可以有各自的工作区和会话，Heartbeat 与定时任务让助手能够持续处理已配置的工作。我认为它的关键价值是把模型能力组织成长期可用的助手，架构上要特别重视状态接续、记忆维护和操作权限。

详细知识笔记展开 / 收起

OpenClaw 的定位

OpenClaw 是一个可自行部署、持续运行的 AI 助手平台。用户可以从飞书等聊天入口发出任务，系统统一管理消息、会话、模型调用、工具执行、记忆和自动化。

它的核心部件是 Gateway：一个长期运行的服务，负责连接消息通道、路由请求、管理会话，并向控制界面和设备节点提供接口。模型是推理能力来源，Gateway 与 Agent 运行时把这种能力组织成能够长期使用的助手。

从产品入口看，它围绕随时从聊天通道发起的长期助手任务组织系统；仓库编码任务可以作为其中的一种工作流。这样容易理解原手册将它与主要围绕代码仓库开展任务的编码助手进行比较的出发点。

一条消息会怎样完成处理？

可以按“入口 → 路由 → 执行 → 返回”来理解：

  1. 通道收到消息。 飞书等适配器接收事件，提取发送者、会话和消息内容。
  2. Gateway 确定处理者。 根据账号、群组或会话绑定，找到对应 Agent 与会话状态。
  3. 准备上下文。 读取 Agent 的工作区规则、必要的用户信息、相关记忆和当前对话。
  4. 执行 Agent 循环。 模型理解任务、选择工具；运行时执行工具并把结果交回模型，直到完成任务或需要进一步输入。
  5. 返回并保存。 将结果流式或完整地发回通道，持久化会话与相关状态，供下一次继续。

Gateway 还提供 WebSocket 控制接口和事件流，控制界面可以观察运行状态，设备节点可以暴露被允许使用的能力。同一会话的运行由系统协调，保持消息和状态更新的顺序。

Gateway 负责入口、路由与整体协调，内嵌 Agent 运行时负责提示组装、模型推理、工具循环、压缩和执行记录。原手册介绍的 Pi 内核体现了这种分工；当前官方文档将内置运行时归为 OpenClaw 自身维护，旧的 pi 名称作为兼容别名，并允许注册其他运行时。

为什么使用文件化工作区？

OpenClaw 把多类长期信息放进 Agent 的工作区，用户能够阅读、编辑和备份。常见内容包括：

文件或内容 用途
AGENTS.md 工作约定、操作规则与相关指引
SOUL.md 助手的表达方式、角色和行为偏好
USER.md 需要长期记住的用户信息与偏好
MEMORY.md 筛选后的长期事实、重要决定与经验
memory/日期.md 当天观察、事件和阶段性记录
Skills 材料 完成某类任务时按需读取的操作方法与资源

工作区保存面向任务的文件。连接配置、凭证和会话运行状态由独立的状态目录管理。部署时可以分别安排版本管理、备份与访问权限。

这种设计使“助手为什么这样做”更容易追踪：可以查看它读到的规则、取回的记忆和工具记录。维护时也可以直接纠正已经过时的偏好或事实。

记忆如何参与长时间任务？

日记式文件先保存近期事件，长期记忆再保存反复使用且较稳定的信息。需要历史知识时，通过记忆搜索找到相关片段，再按需读取原文；检索后端可以组合关键词与语义检索。

上下文即将压缩时，可以先把重要的新信息写入持久记忆，再压缩当前会话。后台整合机制则从近期记录中筛选适合长期保留的内容，整理到长期记忆，并留下可检查的记录。

这样，当前上下文主要装本轮任务需要的信息，持久记忆承担跨会话积累。记忆维护还要处理过期事实、冲突记录和信息归属，使取回内容与当前任务相符。

飞书通道怎样接入？

飞书适配器通过应用身份接收消息事件并发送回复。当前官方接入方式以 WebSocket 长连接为默认入口，也提供 Webhook 配置；支持私聊、群聊以及流式卡片回复。

通道层处理消息格式、身份和会话标识；Gateway 把消息交给对应 Agent；Agent 完成后再经同一通道返回。配对、允许列表和群组规则用于控制谁可以触发哪些任务，具体工具权限与执行环境另行按 Agent 配置。

这种分层把“消息从哪里来”和“任务怎样执行”分开管理，接入多个入口时可以复用后面的执行流程。

多 Agent、工具和 Skills 如何配合？

可以为不同 Agent 配置独立工作区、会话与模型设置，再按通道、账号或会话进行路由。例如工作助手读取工作资料，生活助手使用另一套规则与记忆。子 Agent 可以承担独立子任务，由主流程收集结果。

工具提供可执行动作，例如读取文件、检索资料、运行命令或操作浏览器；Skills 提供如何完成某类工作的说明和相关资源；插件可以扩展通道、工具等系统能力。运行时根据任务和配置把这些能力提供给模型，并管理实际执行。

兼容 bundle 的作用是复用其他生态的能力包：系统识别包内的材料，把支持的内容映射到本地 Skills、Hooks 或 MCP 工具。原生插件则可以在进程内注册更广的系统能力；选择扩展方式时，根据需要提供的是操作说明、工具连接还是运行时代码来区分。

配置时要把身份、数据范围、工具权限和执行隔离一起组织清楚。工作区分开之后，仍需为各 Agent 配好实际可访问的资源与操作范围。

官方的部署信任模型是一个 Gateway 对应一个可信操作者或彼此信任的团队。需要强隔离的不同用户或组织，分别部署 Gateway，并配合独立系统用户或主机划分权限与数据。

Heartbeat 与定时自动化分别做什么？

Heartbeat 用于周期性唤起助手，结合主会话上下文检查是否有值得处理的新情况，例如待办变化；有明确结果时再反馈。定时任务面向指定时间或固定周期的工作，例如每天生成摘要，或者在约定时间执行一次检查。

当前文档把这些能力放在统一的 Automations 调度体系中：保存调度状态，在时间或事件到达时触发任务，并将结果投递到消息通道等目标。Heartbeat 与任务自身的定时运行可以采用不同执行语义，按实际需要选择。

常驻助手因此既能响应即时消息，也能在已配置的任务触发时主动工作。长期运行时要一起观察调用成本、失败重试和消息频率。

面试中值得强调的设计取舍

OpenClaw 把多入口、会话、文件化记忆、工具和调度整合在一个可控制的环境里，适合持续使用的助手工作流。它也把配置维护、凭证管理、更新和运行成本交给部署者处理。

我会关注三件事：任务跨会话能否正确接续，重要信息能否查到来源并维护，以及外部操作能否根据明确身份和权限执行。这三件事直接决定一个长期在线助手的可用性。
