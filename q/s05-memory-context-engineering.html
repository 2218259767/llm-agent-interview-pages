题目

工业界如何组织长期 Agent 的上下文与记忆？

面试口述回答

工业界通常把长期 Agent 的记忆放进上下文工程一起设计：当前窗口保存这一步要用的目标和证据，窗口外用持久笔记保存进度、决策和来源。需要细节时再按文档 ID 或文件路径取回，这就是按需检索。历史变长后，用 compaction 把已完成部分压缩成能继续工作的摘要，用 context editing 清理已经用过的冗长工具结果；重要状态先写入笔记，之后仍能回查。复杂任务可以拆给拥有独立上下文的子 Agent，让它们回传结论和证据，由主 Agent 整合。对于每次都会重复的系统说明、工具定义和背景资料，再利用 prompt caching 减少重复前缀计算。我会重点检查这些环节交接时，目标、约束、有效状态和证据是否都保留下来了，再用跨会话任务的成功率、时延和成本判断方案效果。

详细知识笔记展开 / 收起

总体思路：把当前工作区与持久状态配合起来

长期 Agent 会连续读取材料、调用工具、修改计划，还需要跨会话接着做。上下文工程负责为每一步组织当前目标、有效状态和必要证据；持久记忆保存任务进度、决定和可复用经验。以 Anthropic 的公开实践为例，可以把系统理解为“当前上下文＋持久笔记或工件＋按需检索＋压缩与清理”。

例如一个持续数天的资料研究任务，当前窗口放正在解决的子问题，笔记保存研究计划、已经确认的结论和待核查事项，原材料通过文件路径或文档 ID 留在外部。新会话读取进度后即可接续。

按需取回：Just-in-time retrieval

先保存轻量引用，例如文档 ID、文件路径、查询条件和简短说明，实际需要细节时再用工具读取原文。开始任务时可以预先加载稳定规则和关键状态，探索过程中按子问题继续检索。

这种组织方式让上下文围绕当前步骤展开。引用中的标题、目录、时间和主体也能帮助 Agent 决定去哪里找材料；检索结果应带回来源，便于复查。

持久笔记：记录能够接续任务的状态

将目标、进度、已经做出的决策、待办和证据引用写入结构化文件或数据库，完成一个阶段后及时更新。Anthropic 的 memory tool 就提供了跨会话保存和读取文件的接口，底层存储由客户端掌控。

一份适合接续的研究笔记，可以分成“当前目标、已确认结论、未解决问题、下一步、来源索引”。后续会话先读这些字段，再按引用取回详细材料。文件大小、有效期和用户访问范围也应随持久层一起管理。

Compaction 与 Context editing：怎样整理越来越长的历史？

Compaction 是摘要压缩：当历史接近设定的上下文阈值时，把已完成部分提炼为摘要，保留目标、关键决策、尚未解决的问题和证据位置，再用摘要与最近必要消息继续任务。摘要字段要围绕后续动作设计，尤其保留已经确定的约束和下一步依赖。

Context editing 是局部清理：针对已经使用过的大段工具结果、重复搜索输出等内容逐项清理或替换成占位说明，同时保留当前仍有用的消息。清理前先将有持续价值的信息写入持久笔记，后续需要细节时沿引用重新读取。

两者可以组合使用：先清理明显冗余的工具结果，历史进一步增长后再做阶段摘要。检查压缩效果时，可以让 Agent 根据整理后的状态继续完成下一步任务，核对约束、结论和依赖是否仍然可用。

子 Agent：在局部上下文中完成子任务

把相对独立的研究问题交给专门子 Agent，每个子 Agent 使用自己的上下文读取材料和调用工具，主 Agent 维护整体计划。子 Agent 完成后回传结论、关键证据引用、尚未解决的问题和建议的下一步。

这样大量探索细节保存在各自的工作过程里，主 Agent 可以集中比较结论和整合结果。回传格式需要保留主任务真正依赖的信息，例如结论适用范围与证据出处，方便主 Agent 复查关键判断。

Prompt caching：复用重复前缀的计算

稳定的系统说明、工具定义和反复使用的背景材料，可以放在请求的公共前缀里。启用 prompt caching 后，在缓存有效期内复用相同前缀的计算，减少重复处理带来的时延和成本。

工程上把相对稳定的内容放前面，把当前问题和变化较快的状态放后面，观察缓存命中情况，再调整缓存边界。跨会话需要长期维护的事实、进度与版本仍由持久记忆层保存；缓存负责让重复输入的处理更经济。

怎样选择起步方案？

可以先建立清晰的持久笔记、引用和按需读取流程，再依据真实任务加入压缩、局部清理或子 Agent。评估时同时观察任务成功率、跨会话接续能力、输入 token、时延和成本，检查每个机制具体改善了哪一部分。
