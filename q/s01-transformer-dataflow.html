Transformer 在训练和推理时，数据是怎样流动的？

追问约 8 分钟
更新于 2026-10-13
这道题接续请介绍一下 Transformer 的整体架构和各个组件的作用。

题目

Transformer 在训练和推理时，数据是怎样流动的？

面试口述回答

我会按 Encoder–Decoder 和 Decoder-only 两种结构讲，并分别看训练和推理。

Encoder–Decoder 训练时，源序列经过 Encoder 生成 Memory，目标序列右移一位送入 Decoder。Decoder 先用因果自注意力读取目标前缀，再用自己的 Query 访问 Encoder 的 Key、Value，最后经 FFN 和词表投影预测目标 token。目标已知，所以可以用 Teacher Forcing 并行计算。推理时 Encoder 算一次，Decoder 则逐步生成，并缓存自注意力和交叉注意力的 K/V。

Decoder-only 把所有条件放进同一条序列，训练时通过因果 Mask 并行做下一 token 预测。推理分为 Prefill 和 Decode：Prefill 处理完整 Prompt、建立缓存；Decode 每次只处理新 token，把新 K/V 追加到缓存后继续生成。两种架构的区别就在于，条件信息是单独编码后读取，还是直接放进自回归前缀。

详细知识笔记展开 / 收起

1. 先看共同入口

文本经过 Tokenizer 变成 token ID，再由 Embedding 映射成 [B,T,D][B,T,D][B,T,D] 的隐藏状态，加入位置机制后送入 Transformer Block。以普通多头注意力为例，每层将隐藏状态投影为 Q、K、V，并拆成 [B,H,T,dh][B,H,T,d_h][B,H,T,dh​]，其中 Hdh=DH d_h=DHdh​=D。每层更新表示，最后 LM Head 将 DDD 维向量投影到词表，得到形状为 [B,T,V][B,T,V][B,T,V] 的 logits；这里形状记号中的 VVV 表示词表大小，每个位置都有一组词表候选分数。

2. Encoder–Decoder 的训练流程

源序列这一侧：源文本经过 Encoder 的双向 Self-Attention 和 FFN，得到 Encoder Memory，形状为 [B,Tsrc,D][B,T_{src},D][B,Tsrc​,D]。源序列中的有效位置可以互相读取，Padding 位置被屏蔽。

目标序列这一侧：将真实目标右移一位作为 Decoder 输入，这叫 Teacher Forcing。例如目标为 [y1, y2, y3, EOS]，输入为 [BOS, y1, y2, y3]。一次前向就能在四个位置上分别预测目标 token。

Decoder 每层先用因果 Self-Attention 读取目标前缀，再做 Cross-Attention：Q 来自当前 Decoder 状态，K/V 来自 Encoder Memory。Cross-Attention 分数形状为 [B,H,Ttgt,Tsrc][B,H,T_{tgt},T_{src}][B,H,Ttgt​,Tsrc​]，目标位置可以读取完整有效源序列。随后经过 FFN，得到这一层更新后的目标序列表示。

最后一层 Decoder 的输出为 [B,Ttgt,D][B,T_{tgt},D][B,Ttgt​,D]，经过词表投影得到 [B,Ttgt,V][B,T_{tgt},V][B,Ttgt​,V] 的 logits。对词表维度做 Softmax，就得到每个目标位置预测下一个 token 的概率分布，再用真实 target 标签计算交叉熵。前面的例子中，四个位置分别以 y1、y2、y3、EOS 为正确标签。这样就把“源序列编码 → 目标前缀读取条件 → 词表预测 → 监督损失”连成了完整路径。

3. Encoder–Decoder 的推理流程

源序列先经过一次 Encoder，得到固定的 Memory。Decoder 从起始符开始，生成 token，再把生成结果作为下一步输入，直到结束符或长度上限。

Decoder 各层的历史 K/V 可以缓存。Self-Attention 的缓存随生成增长；Cross-Attention 的 K/V 由固定的 Encoder Memory 投影得到，可以复用。每一步的新 token 都会生成自己的 Q、K、V，其中新 K/V 追加到自注意力缓存。

4. Decoder-only 的训练流程

所有条件组织为同一条序列，例如“系统指令—用户问题—助手回答”。训练目标是

L=−∑tlog⁡pθ(xt+1∣x≤t).\mathcal L=-\sum_t\log p_\theta(x_{t+1}\mid x_{\le t}).L=−t∑​logpθ​(xt+1​∣x≤t​).

输入 [t1,t2,t3]，对应的预测标签是 [t2,t3,t4]。因为真实 token 已知，可以一次计算整段序列；因果 Mask 负责限制每个位置的信息来源。

多层 Block 输出 [B,T,D][B,T,D][B,T,D] 的隐藏状态，LM Head 把它映射为 [B,T,V][B,T,V][B,T,V] 的 logits。其概率解释同样是沿词表维度做 Softmax，再用右侧相邻 token 作为正确标签计算交叉熵；实际交叉熵实现可以直接接收 logits 并完成内部的 LogSoftmax 计算。

预训练通常对有效文本位置计算损失，指令微调常仅监督助手回答。Attention Mask 决定读哪些位置，Loss Mask 决定哪些预测计入训练目标：问题内容仍供模型读取，回答部分提供主要监督。

5. Decoder-only 的推理：Prefill 与 Decode

Prefill 一次处理整个 Prompt，建立各层 KV Cache，并用最后一个位置的 logits 采样首个回答 token。

Decode 每步处理最新生成的 token，计算新 Q/K/V，用新 Query 读取历史和当前的 K/V，再输出下一 token。缓存节省了历史 token 的重复前向计算。

因此训练和推理的差异来自输入是否已知：训练时目标序列已知，各位置能并行计算；生成时下一输入由当前输出决定，需要逐步推进。Prefill 和 Decode 的计算特点也不同，服务系统因此分别关注首 token 延迟和后续 token 生成速度。

6. 把两种架构的数据路径放在一起比较

比较项 Encoder–Decoder Decoder-only
序列组织 源序列与目标序列分开，分别送入 Encoder 和 Decoder 指令、问题、上下文和回答组织在同一条自回归序列中
条件信息怎样进入生成过程 源序列先得到 Memory，Decoder 通过 Cross-Attention 读取 条件直接放进前缀，后续位置通过因果 Self-Attention 读取
训练时预测什么 目标右移后送入 Decoder，各位置预测真实 target token 整段输入并行计算，各位置预测右侧下一个 token
推理时复用什么 Encoder Memory 及其 Cross-Attention K/V 固定复用，Decoder Self-Attention K/V 随生成增长 Prefill 建立前缀 K/V，Decode 逐步追加新 token 的 K/V
典型建模方式 翻译、摘要等有明确源序列与目标序列的 seq2seq 任务 把多种任务统一组织成前缀条件下的下一 token 预测

从数据流看，Encoder–Decoder 是源序列先编码，再条件生成目标序列；Decoder-only 是把所有条件放进前缀，再自回归补全后面的 token。两者最后都通过词表投影完成 token 预测，主要差别在于条件信息如何组织和读取。
