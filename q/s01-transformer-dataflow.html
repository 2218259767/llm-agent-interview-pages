Transformer 在训练和推理时，数据是怎样流动的？

追问约 23 分钟
更新于 2026-10-19
这道题接续请介绍一下 Transformer 的整体架构和各个组件的作用。

题目

Transformer 在训练和推理时，数据是怎样流动的？请分别说明 Encoder–Decoder 和 Decoder-only 的输入、输出、训练标签与生成过程，并解释 Prefill、Decode 及 PD 分离的联系。

面试口述回答

我会先讲 Encoder–Decoder，再讲 Decoder-only，分别说明训练和推理时的数据流。

首先是 Encoder–Decoder。训练时，Encoder 输入源序列 Source Sequence，token ID 的形状是 [B,S]，其中 S 是这个 batch Padding 后的源序列长度。经过 Embedding 和多层 Encoder 后，输出 [B,S,D] 的上下文表征。也就是说，每个源 token 都对应一个融合上下文的 D 维向量，整句保留为一组向量。

Decoder 这边输入真实目标序列，但需要和预测标签错开一位。比如目标正文是 [y1,y2,y3]，Decoder 输入 [BOS,y1,y2,y3]，标签是 [y1,y2,y3,EOS]。这样，输入 BOS 的位置预测第一个 token，输入最后一个目标 token 的位置预测 EOS。

训练时真实目标已知，所以这段输入可以并行送进 Decoder，这叫 Teacher Forcing。为保证自回归关系，Decoder 每层第一个多头自注意力使用因果 Mask：第 t 个输入位置只能读取第 1 到第 t 个位置的 Key 和 Value。未来位置的注意力分数在 Softmax 前设为负无穷，使其注意力权重为 0。

接着，Cross-Attention 用 Decoder 当前状态产生 Query，用 Encoder 输出产生 Key 和 Value，读取源序列的信息。最后一层 Decoder 输出的是 [B,T,D] 的隐藏状态，再经过词表投影，得到 [B,T,V_vocab] 的 logits；沿词表做 Softmax 后，才得到每个位置的概率分布。从单个位置看，这是一个词表大小的多分类问题，用对应真实 token 计算交叉熵。实际训练可以直接把 logits 交给交叉熵函数，Padding 标签不计入损失。

推理时，Encoder 先并行编码整个源序列，得到可复用的 Memory。Decoder 从 BOS 开始生成，将已经选出的 token 作为后续输入，逐步预测下一个 token，直到 EOS 或生成长度上限。因此，Encoder–Decoder 的目标端本身也是条件式的 Next Token Prediction。使用 KV Cache 时，可以复用历史自注意力 K/V，以及由固定源端 Memory 得到的交叉注意力 K/V。

接下来是 Decoder-only。它可以把翻译、摘要、扩写、文本分类等很多任务统一组织成“输入 Prompt，再自回归生成后续结果”。模型用因果自注意力读取前缀。

它常见的预训练目标是 Next Token Prediction，属于自监督学习：标签直接来自原始文本，无需为每个 next token 额外人工标注。比如一段文本是 [A,B,C,D,E,F]，可以把输入写成 [A,B,C,D,E]，标签写成 [B,C,D,E,F]。A 所在位置预测 B，看到 A、B 的位置预测 C，以此类推；这些位置在训练时可以并行计算，因果 Mask 负责限制各自能看到的前缀。损失是正确下一个 token 的交叉熵，也就是负对数似然。

Decoder-only 的推理通常分为 Prefill 和 Decode。Prefill 把已知 Prompt 的所有 token 并行送入模型，建立每层 KV Cache，并根据最后一个 Prompt 位置的输出选择第一个新 token。Decode 则逐步把新生成的 token 送入模型，计算它的 Q、K、V，追加新 K/V，并利用历史缓存继续预测后续 token，直到满足停止条件。

两阶段的计算特点不同。Prompt 较长时，Prefill 通常有较高计算强度，更容易受 GPU 算力限制；常见小 batch 下，Decode 每步处理的新 token 少，却要读取大量模型权重和历史 KV，往往受显存带宽限制。KV Cache 的显存占用则主要影响可支持的上下文长度和并发量，具体瓶颈也会随 batch 和硬件变化。

因此，一些服务系统采用 PD 分离，把 Prefill 和 Decode 交给不同执行实例或 GPU 资源池，分别调度和扩缩容；Prefill 完成后将 KV Cache 交给 Decode 端继续生成。这样可以减少两阶段的资源干扰，但也要考虑缓存传输开销。这些资源可以部署在同一集群中。

详细知识笔记展开 / 收起

1. 共同入口与形状约定

文本首先经过 Tokenizer 变成 token ID。以一个 batch 的源序列为例，输入 ID 张量为 [B,S]：B 是 batch size，S 是这个 batch Padding 后的源序列长度。真实句子长度可以各不相同，Padding Mask 标记哪些位置有效。经过 Token Embedding 和位置机制后，得到 [B,S,D] 的隐藏状态，D 为模型宽度。

Encoder 最后输出的 Memory 仍是 [B,S,D]。它表示每个源 token 各有一个包含上下文信息的 D 维向量，合起来构成一组上下文表征。标准 Transformer 保留这个源端位置维度，Decoder 随后可以按需要关注不同源位置。

普通多头注意力中，隐藏状态分别经过 Q、K、V 投影，再拆成 [B,H,T,d_h]，其中 H 是头数，H d_h=D。这里 T 表示当前处理的序列长度；源长度 S 与目标长度 T 可以不同。下文用 V_vocab 表示词表大小，避免与注意力中的 Value 混淆。

2. Encoder–Decoder 训练：源端编码、目标右移与并行预测

2.1 Encoder 编码源序列

源序列 [B,S] 经过 Embedding 和 Encoder 的多层双向 Self-Attention、FFN 等组件，得到 [B,S,D] 的 Memory。源端有效 token 可以相互读取；Attention 读取源端时应屏蔽 Padding。输入和输出的源位置数量对应，表示内容则逐层融合了上下文。Transformer 原论文 §3.1–3.2

2.2 Decoder 的输入与标签怎样对齐

以目标正文 token 为 [y1,y2,y3]、使用 BOS/EOS 为例：

text
Decoder 输入： [BOS, y1, y2, y3]
正确预测标签： [ y1, y2, y3, EOS]

四个位置分别学习 BOS→y1、BOS,y1→y2、BOS,y1,y2→y3 和完整目标前缀后预测 EOS。因此，更准确地说，是输入真实目标前缀，预测下一个真实目标 token。输入最后一个目标 token y3 的位置负责预测 EOS。

如果目标正文有 m 个 token，则这个例子的 Decoder 输入和标签都长 m+1；batch 内再 Padding 到目标长度 T，两者形状均为 [B,T]。若某实现存储的 target 已经含有 EOS，就用起始符和去掉最后一位的 target 组成 Decoder 输入；关键是保持上面的逐位置对齐。具体起始 token 的定义依模型约定，这里沿用 BOS 便于说明。

训练时真实目标已知，可以把所有这些输入位置一次送入 Decoder，这种使用真实历史 token 的方式叫 Teacher Forcing。并行的是各个序列位置的计算，多层 Block 仍然逐层处理。Transformer 原论文 §3.1

2.3 因果 Mask 为什么允许并行训练

Decoder 每层的第一个多头 Self-Attention 使用因果 Mask。在输入位置 t，Query 可以读取位置 1 到 t 的 Key/Value；位置 j>t 的注意力分数在 Softmax 前被设为负无穷。可写为：

A=softmax⁡ ⁣(QK⊤dk+M),Mtj={0,j≤t,−∞,j>t.A=\operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}+M\right),\qquad M_{tj}=\begin{cases}0,&j\le t,\\-\infty,&j>t.\end{cases}A=softmax(dk​​QK⊤​+M),Mtj​={0,−∞,​j≤t,j>t.​

这样，未来位置对应的注意力权重为 0。当前位置的输入 token 可以被读取，当前位置要预测的是它后面的 token。即使真实目标整段已输入，模型在各位置仍然只能利用该位置允许的前缀。Padding Mask 还要屏蔽无效填充位置。两种 Mask 共同保证“可读取的信息”符合任务设定。Transformer 原论文 §3.2.1、§3.2.3

2.4 Cross-Attention、词表投影与交叉熵

完成目标端 Self-Attention 后，Cross-Attention 的 Q 来自当前 Decoder 状态，K/V 来自 Encoder Memory 的投影。普通多头实现中，注意力分数形状为 [B,H,T,S]，每个目标位置都可以关注完整有效源序列。随后经过 FFN 等组件更新目标表示。

最终输出路径为：

text
Decoder 最后一层隐藏状态  [B,T,D]
             ↓ LM Head / 词表线性投影
logits（未归一化词表分数） [B,T,V_vocab]
             ↓ 沿词表维度 Softmax
每个位置的词表概率分布     [B,T,V_vocab]

因此，每个有效目标位置都可以看成一个 V_vocab 类的条件分类问题，正确类别就是对应的真实 token ID。整个序列的概率由这些条件概率相乘得到；取负对数便成为各位置损失之和：

Lseq2seq=−∑t=1m+1log⁡pθ(yt∣x,y<t),ym+1=EOS.\mathcal L_{\mathrm{seq2seq}} =-\sum_{t=1}^{m+1}\log p_\theta(y_t\mid x,y_{<t}),\qquad y_{m+1}=\mathrm{EOS}.Lseq2seq​=−t=1∑m+1​logpθ​(yt​∣x,y<t​),ym+1​=EOS.

这里的 x 是完整源序列。训练通常对 batch 中有效标签位置求和或平均，Padding 标签不计入损失。对于真实 token ID 这样的类别标签，交叉熵等于该正确 token 条件概率的负对数。Transformer 原论文 §3.4

实现上可直接把 logits 交给 CrossEntropyLoss，由它完成 LogSoftmax 等计算；讲解中的 Softmax 用于说明概率含义。PyTorch 的类别维接口要求具体排布，实际可展平为 [B*T,V_vocab] 配 [B*T] 标签，或调整到相应类别维。忽略 Padding 由标签掩码/ignore_index 等机制完成。PyTorch CrossEntropyLoss

3. Encoder–Decoder 推理：固定源端，逐步生成目标

推理时，Encoder 仍并行处理整个源序列，通常每条请求只计算一次，得到固定 Memory。Decoder 以 BOS 等约定起始符为起点，先预测第一个目标 token；根据 logits 进行贪心选择、采样或其他解码，再把选出的 token 作为后续输入。比如生成 y1 后，接着根据源序列与 [BOS,y1] 预测 y2，如此继续，直到 EOS 或配置的生成长度上限。Transformer 原论文 §3.1

因此，Encoder–Decoder 的目标端本身也在做条件式的 Next Token Prediction。训练时可以读取真实历史 token；推理时依赖模型已经生成的历史 token。

使用 KV Cache 时，每层 Self-Attention 的历史 K/V 随生成逐步追加。每步新输入 token 仍要计算自己的 Q、K、V：新 Query 读取缓存中的历史 K/V 和当前 K/V，新 K/V 写回缓存。源端 Memory 固定，因此 Cross-Attention 投影得到的源端 K/V 可以预先计算并在后续步骤复用。Transformers KV Cache

长度上限可对应服务中的最大生成 token 数等配置；参数名与“是否包含 Prompt 长度”的语义以具体接口为准。生成在遇到结束符或达到配置的长度上限时停止。

4. Decoder-only 训练：用文本自身构造监督标签

Decoder-only 使用因果 Self-Attention 读取同一条序列的前缀。对于常见的因果语言模型预训练，目标就是预测下一个 token，监督标签直接来自原始文本，因此属于自监督学习。Transformers Causal Language Modeling

例如，文本由 [A,B,C,D,E,F] 六个 token 组成。教学上可以显式写为：

text
模型输入： [A, B, C, D, E]
预测标签： [B, C, D, E, F]

第一位置只看到 A，预测 B；第二位置看到 A、B，预测 C；依次到第五位置根据 A 到 E 预测 F。这五个位置可以在一次前向中并行计算，因果 Mask 限制各自能看到的前缀。按 A→B 解释监督关系是正确的；真实训练会同时利用整段中多个相邻位置的预测任务。

若整段有 L 个 token，其基本目标可写为：

LCLM=−∑t=1L−1log⁡pθ(xt+1∣x≤t).\mathcal L_{\mathrm{CLM}} =-\sum_{t=1}^{L-1}\log p_\theta(x_{t+1}\mid x_{\le t}).LCLM​=−t=1∑L−1​logpθ​(xt+1​∣x≤t​).

经过各层 Block 后，隐藏状态 [B,T,D] 经 LM Head 得到 [B,T,V_vocab] 的 logits，再与对应下一个 token 标签计算交叉熵。这与负对数似然具有相同的目标含义。训练标签确实存在，只是由文本自动构造，免去了为每个 next token 额外人工标注。

工程中，有些框架接受相同的 input_ids 和 labels，在模型内部做移位；有些实现显式构造上述输入/标签。应检查具体实现，确保只做一次正确对齐。Transformers 训练示例

在任务组织上，翻译、摘要、扩写、文本情感分类等都可写成“任务说明和待处理文本作为 Prompt，目标结果作为后续生成”。例如分类时，让模型生成某个类别词。这样，很多文本任务共享自回归生成接口；结构与训练目标的一致性便于大规模训练和复用。架构与规模化比较另见 为什么生成式大模型普遍采用 Decoder-only 架构？。

训练监督范围依阶段与配置区分：预训练通常对有效文本位置计算 next-token 损失；指令微调也可按数据格式，仅对 completion 或助手回答计算损失。Attention Mask 决定模型可以读取哪些位置，Loss Mask 决定哪些位置的预测参与优化。例如问题仍是可读上下文，而只有回答标签贡献损失。具体监督范围依训练配置，并非所有 SFT 都自动只监督助手。TRL SFT Trainer：completion_only_loss / assistant_only_loss

5. Decoder-only 推理：Prefill、Decode 与 KV Cache

5.1 Prefill 处理已知 Prompt

Prompt 的 n 个 token 已经全部已知，因此可以一次并行送入模型。每层仍按因果 Mask 读取合法前缀，并计算、保存这 n 个 token 的 K/V，形成该层 KV Cache。最后一个 Prompt 位置的 logits 用来选择第一个新生成 token。Transformers KV Cache

5.2 Decode 逐步追加生成结果

选出第一个新 token 后，将它作为下一步的新输入。模型计算它在各层的 Q/K/V，把新 K/V 追加到对应缓存；新 Query 读取已有历史和当前的 K/V，得到用于预测后续 token 的 logits。后续每步重复该过程，直到满足停止条件。

历史 K/V 可被复用，是因为标准因果 Decoder 中历史位置看不到未来，追加后续 token 后，已有位置的表示保持可复用。缓存保存每层历史计算结果，省去对整个历史序列的重复前向计算。缓存同时服务于 Prompt 和已生成 token，并从 Prefill 延续到 Decode。Transformers KV Cache

Prefill 与 Decode 的并行性差异来自输入是否已知：Prompt 已知，可并行算各位置；生成内容未知，下一步输入来自本步选出的 token，单条序列因此按时间步推进。服务中常用 TTFT 关注首 token 延迟，用 TPOT/ITL 或生成速度关注后续 token 的逐步生成表现。

5.3 算力、带宽与容量怎样分别影响两阶段

当 Prompt 含较多 token 时，Prefill 能将多个位置组织为矩阵乘法，充分复用已读取的权重，通常有较高算术强度，更容易受 GPU 计算能力约束。

常见小 batch 的自回归 Decode 每步每条序列只处理一个新 token。单步有效计算量较小，仍需要读取大量模型权重和历史 KV，计算相对于数据搬运的比例较低，单步速度往往受显存带宽约束。并发/batch、上下文长度、硬件和并行方式都会改变实际瓶颈；较大 batch 可以复用权重读取，提升 Decode 的计算强度。NVIDIA 推理优化文章正文、DistServe §2、附录 A.3

显存容量则决定模型权重、KV Cache 等能否装下，以及能支持多长的上下文、多少并发序列。上下文越长、并发越大，KV Cache 通常越大。容量不足会限制可用 batch，也可能导致换出/重算等额外代价；它与单步解码时“每秒能读取多少数据”的带宽是不同的资源维度。KV Cache 的容量需求与数据读取带宽会共同影响推理资源配置。NVIDIA 推理优化文章正文

6. PD 分离：按阶段分别配置与调度资源

Prefill–Decode 分离将两阶段交给不同的执行实例或 GPU 资源池，使它们能够分别选择资源配置、并行方式和扩缩容策略，减少长 Prompt 的 Prefill 与逐 token Decode 之间的资源干扰，分别优化首 token 延迟与后续生成延迟。DistServe 论文与系统说明

Prefill 端算完 Prompt 后，需要把 KV Cache 交给 Decode 端，后者才能接续已有上下文。这些实例可以在同一节点、同一集群的不同节点，或跨其他资源部署，具体由实现与带宽条件决定；“不同集群”只是可能的部署形式。分离带来的调度收益需要与 KV 交接的数据搬运、通信及排队开销一起评估。DistServe §4

7. 两种架构的数据路径比较

比较项 Encoder–Decoder Decoder-only
序列组织 源序列和目标前缀分开 指令、问题、上下文和回答组织在同一条序列中
条件信息如何读取 Encoder 得到源 Memory，Decoder 用 Cross-Attention 读取 条件放在前缀，由因果 Self-Attention 读取
训练如何预测 用真实目标前缀并行预测对应下一个目标 token 用文本前缀并行预测右侧相邻 token
推理复用什么 固定 Encoder Memory 与源端 Cross-Attention K/V，逐步追加目标端 Self-Attention K/V Prefill 建立前缀 KV，Decode 逐步追加新 token 的 KV
最终输出 Decoder 隐藏状态→词表 logits→token 条件概率 Decoder 隐藏状态→词表 logits→token 条件概率

从数据流看，两者都能自回归生成目标序列。条件信息是分别编码后供 Decoder 读取，还是直接作为 Decoder 的前缀，是本题比较的主要区别。
