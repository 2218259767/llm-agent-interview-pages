模型家族／Qwen（千问）系列

Qwen3 相比于 Qwen2.5 和 Qwen2 有哪些改进？

约 5 分钟
更新于 2026-10-13

题目

Qwen3 相比于 Qwen2.5 和 Qwen2 有哪些改进？

面试口述回答

Qwen3 相比 Qwen2 和 Qwen2.5，我会重点讲四方面。第一是把思考和非思考模式融合进同一个模型，复杂任务可以展开推理，简单任务直接回答，还能用 Thinking Budget 控制计算投入。

第二是底座数据升级，预训练扩到 36T token，语言和方言覆盖从 Qwen2.5 的 29 扩到 119，并加强代码、STEM 和合成数据。第三是架构上的调整：保留 GQA、RoPE、SwiGLU 等主干，去掉 QKV bias、加入 QK-Norm；MoE 使用 128 选 8 的细粒度专家，并取消共享专家。

第四是后训练：先用长 CoT 冷启动和推理 RL 建立能力，再做模式融合与通用 RL，小模型通过强到弱蒸馏学习。对我来说，最有启发的是它把模型能力和推理资源调度连接起来，让应用能够按问题复杂度分配思考预算。

详细知识笔记展开 / 收起

1. 先认识 Qwen3

Qwen3 是千问系列的第三代语言模型。本题讨论 2025 年 5 月技术报告中的首发系列：包含 0.6B 到 32B 的 Dense 模型，以及 30B-A3B、235B-A22B 两个 MoE 模型。旗舰 MoE 的 235B 是总参数，A22B 表示每个 token 约激活 22B 参数。

和 Qwen2、Qwen2.5 比较，可以沿着使用方式、训练数据、模型架构、后训练四条线展开。

2. 使用方式：思考和直接回答融合

Qwen2.5 的通用指令模型、QwQ 推理模型分别承担不同使用需求。初版 Qwen3 将 Thinking 与 Non-thinking 行为融合到同一个模型：复杂问题可以先生成推理过程，简单请求可以直接回答，通过模板与 /think、/no_think 控制。

Thinking Budget 进一步控制用于思考的生成长度。应用可以根据任务难度分配计算，例如把预算优先给多步数学和复杂代码任务，让日常交互保持较低延迟。

3. 数据：规模与覆盖面扩大

Qwen3 预训练使用约 36T token，Qwen2.5 报告对应约 18T；语言与方言覆盖从 Qwen2.5 的 29 扩展到 119。数据包含代码、STEM、书籍、多语言文本与合成内容。

数据生产也利用前代模型：用视觉模型从 PDF 等材料识别文本，用语言模型清理，再用数学、代码等专门模型生成高质量内容。预训练分阶段组织：先建立通用语言和知识，再提高推理相关数据比例，最后进行长上下文训练。报告中训练长度从 4K 扩展到 32K，并通过 YaRN、DCA 等配置进一步扩展推理窗口。

4. 架构：延续主干，调整注意力与 MoE

Dense 模型继续使用 GQA、RoPE、SwiGLU 和 Pre-Norm RMSNorm。相对前代，两个明确改动是：

  • **去掉 QKV-bias：**Q、K、V 的投影使用无偏置线性层。
  • **引入 QK-Norm：**注意力点积前归一化 Q、K 的尺度，帮助大规模训练稳定。

MoE 使用细粒度专家，报告配置为 128 个专家、每 token 激活 8 个，去掉 Qwen2.5-MoE 路线中的共享专家，并采用全局 batch 负载均衡。这样通过稀疏激活提高容量，同时管理专家分工。

5. 后训练：四阶段路线与小模型蒸馏

旗舰模型先进行 Long-CoT 冷启动和 Reasoning RL，建立推理能力；再通过 Thinking Mode Fusion 的混合 SFT，学习思考与直接回答；最后使用 General RL 改善通用指令、对齐和 Agent 等能力。

小模型采用强到弱蒸馏：先学习教师生成的高质量响应，再在学生生成的轨迹上用教师分布提供指导。这样把大模型建立的推理和回答能力迁移到较小模型。

我认为这次迭代最有价值的联系是：底座的数据和架构升级提供能力，后训练让能力以不同模式被调用，推理预算再把它转成可控制的成本与延迟。
