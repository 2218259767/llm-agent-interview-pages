RAG 检索增强生成／多模态 RAG

将图片转成 Caption 后做 RAG，有什么局限？如何改进？

约 3 分钟
更新于 2026-10-13

题目

将图片转成 Caption 后做 RAG，有什么局限？如何改进？

面试口述回答

把图片转成 Caption 做 RAG 的优势是简单，能直接复用文本检索系统。但它把图片压缩成了一段固定描述，用户后续问到的纹理、部位或小字可能恰好被省略；描述阶段的识别错误也会沿着检索链路传递。对于商品详情页，我会保留 Caption 作为辅助，同时存原图和区域信息，增加视觉向量检索，再把命中的关键图片交给多模态模型读取。这样整体语义走便宜的文本路径，细节问题还能回到原始视觉证据，系统的成本和效果也更容易按任务调节。

详细知识笔记展开 / 收起

这种方案怎样工作？

Caption-based RAG 先用视觉模型把图片描述成文本，再对描述建立文本索引。检索到相关描述后，语言模型结合文字作答。这种方式容易复用已有文本 RAG 管线，适合主要关注图片整体语义的任务。

为什么商品细节问答容易遇到瓶颈？

信息压缩。 一段 Caption 只能选择性描述图片。它可能写了“红色运动鞋”，却省略鞋底花纹、领口材质、细小标识等用户后来关心的内容。查询发生在描述生成之后，因此生成 Caption 时很难预知所有问题。

描述误差传递。 如果描述阶段将圆领识别成 V 领，检索和生成都会围绕错误文字继续处理。保留原图，可以在后续阶段重新核实视觉证据。

局部结构表达不足。 商品详情长图、表格和密集文字涉及区域与位置，整图摘要难以保留所有细粒度关系。

怎样改进现有系统？

  1. 保留原图和来源信息：Caption 作为辅助检索文本，同时保存图片 ID、商品 ID、区域与版本。
  2. 增加视觉检索路径：使用图文对齐模型建立图片向量；长图或文档页可切分区域，或采用多向量检索表示局部特征。
  3. 融合检索结果：文字索引擅长标题、型号和 OCR，视觉索引帮助匹配外观与局部内容；在商品/图片层融合后重排。
  4. 生成阶段回看证据：将最相关原图或裁剪区域与商品资料提供给视觉语言模型，使回答能利用实际检索到的图像。

ColPali 是文档页视觉多向量检索的一个代表，可用于理解“保留局部视觉表示、用后交互匹配”的思路。具体商品场景可先从整图与关键区域索引开始，再根据细节召回效果增加复杂度。

怎样选择路线？

关注宏观描述、成本敏感的任务，可以先使用 Caption 加文本 RAG；纹理、局部款式、图表布局或小字问答，则更适合保留图像检索与视觉读取路径。通过整体问题、细节问题和 OCR 问题分组评估，判断需要增加哪一层能力。
