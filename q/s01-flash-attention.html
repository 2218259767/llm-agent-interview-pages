FlashAttention 是什么？

约 5 分钟
更新于 2026-10-13

题目

FlashAttention 是什么？

面试口述回答

FlashAttention 是一种面向 GPU 访存优化的精确注意力算法。普通 Attention 会把序列长度平方大小的分数矩阵和概率矩阵反复写入、读出显存，这在长序列下开销很大。FlashAttention 把 Q、K、V 分块放进高速片上存储，利用 Online Softmax 维护当前最大值、指数和以及加权输出，逐块得到完整的注意力结果。训练反向传播时，再根据保存的统计量重算局部概率，省去保存巨大中间矩阵的成本。我觉得它最关键的思路是：结合 GPU 的存储层级重新组织计算，用少量重计算换取大幅减少的 IO 和显存占用。

详细知识笔记展开 / 收起

定义：面向 GPU 访存优化的精确注意力算法

FlashAttention 通过分块、融合计算和重计算，减少注意力计算在 GPU 主显存 HBM 与片上高速存储之间的数据搬运。它计算的目标仍是标准注意力：

O=softmax⁡(QK⊤dk)V.O=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V.O=softmax(dk​​QK⊤​)V.

理解它可以从 GPU 的两级存储出发：HBM 容量大，适合存放模型和张量；片上 SRAM 容量小、访问快，适合计算时反复使用的数据。FlashAttention 尽量让中间结果留在片上完成后续计算。

普通注意力为什么耗显存、耗 IO？

对长度为 NNN 的序列，普通实现先生成 N×NN\times NN×N 的分数矩阵 SSS，再做 softmax 生成概率矩阵 PPP，最后计算 PVPVPV。这些中间矩阵写入 HBM、再被后续算子读回，长序列下会产生大量访存和存储开销。

核心一：分块计算与 Online Softmax

算法把 Q、K、V 切成适合片上存储的小块。固定一块 Q，依次读入 K、V 的各个块，计算局部分数并累计输出。

softmax 的分母需要整行指数之和，因此分块时要维护三项状态：已经见过的分数最大值 mmm、指数和 ℓ\ellℓ、以及未归一化的加权和 uuu。当新块分数为 sjs_jsj​、对应值为 vjv_jvj​ 时：

m′=max⁡(m,max⁡jsj),m'=\max(m,\max_j s_j),m′=max(m,jmax​sj​),
ℓ′=em−m′ℓ+∑jesj−m′,u′=em−m′u+∑jesj−m′vj.\ell'=e^{m-m'}\ell+\sum_j e^{s_j-m'},\qquad u'=e^{m-m'}u+\sum_j e^{s_j-m'}v_j.ℓ′=em−m′ℓ+j∑​esj​−m′,u′=em−m′u+j∑​esj​−m′vj​.

所有块处理完，输出为 O=u/ℓO=u/\ellO=u/ℓ。其中 em−m′e^{m-m'}em−m′ 把旧累积量换算到新的最大值尺度上；这样只需保留少量统计量，就能逐块完成整行 softmax 与加权求和。数学上这对应完整的稠密注意力，浮点执行采用数值稳定的缩放。

核心二：反向传播时重计算

训练的前向阶段保存 Q、K、V、输出及每行归一化统计量。反向传播需要局部概率时，在片上重新计算相应分块，随用随算。原先需要保存的完整 N×NN\times NN×N 中间矩阵由线性规模的统计量替代。

这体现了“用额外计算换更少数据搬运”：GPU 算术吞吐很高，重新计算局部分数的代价，往往低于反复读写大矩阵。标准稠密注意力的算术量为 O(N2d)O(N^2d)O(N2d)，优化重点是 IO 和中间存储。

版本延伸：FlashAttention-2 与 FlashAttention-3

FlashAttention-2 进一步提高 GPU 的计算利用率：减少非矩阵乘法操作，把单个注意力头的工作分给更多线程块，同时改善线程块内部的任务划分，减少共享内存通信。它沿用分块和在线归一化的基础，重点解决并行度与工作分配问题。FlashAttention-2 论文

FlashAttention-3 面向 Hopper 架构 GPU，利用异步 Tensor Core 和 TMA 数据搬运，让计算与访存重叠，并将分块矩阵乘法与 softmax 交错执行；同时结合分块量化等方法发挥 FP8 低精度计算吞吐。理解这条演进路线，可以把第一代的访存优化、第二代的并行优化和第三代对新硬件异步能力的利用串起来。FlashAttention-3 论文

常见追问：和 PagedAttention 有什么区别？

FlashAttention 优化一次注意力计算中的数据搬运；PagedAttention 管理推理期间持续增长的 KV Cache。训练、长 prompt 的 prefill 通常特别关注前者，推理服务的缓存容量和并发管理则会结合后者。

实际接入时，可通过框架提供的注意力后端或专用库使用，关注硬件、精度、head dimension 与 mask 的支持情况，再测量目标长度下的显存和耗时。
