Agent／Agent 架构与工作流

除了模型能力，Agent 的运行系统还能从哪些方面提升效果？

约 5 分钟
更新于 2026-10-13

题目

除了模型能力，Agent 的运行系统还能从哪些方面提升效果？

面试口述回答

除了模型，Agent 的效果还取决于围绕它的运行系统，也就是 Harness。它负责给模型准备上下文、提供工具、执行动作、保存状态和检查结果。我会重点优化几件事：用持久规则和记忆继承任务约定，按需加载信息，给工具清楚的输入输出契约，并做好超时、检查点和中断恢复。多轮任务还要保存目标、已确认事实、待解决问题和每次操作结果。比如修改订单地址后，要保留订单号和操作回执，下一轮才能正确接续。最后固定模型做任务评测，分析失败究竟来自上下文丢失、工具使用还是执行恢复，再改对应环节。

详细知识笔记展开 / 收起

Agent 的运行系统是什么？

模型负责理解输入、推理和选择下一步行动；围绕模型的运行系统负责准备上下文、提供工具、执行动作、保存状态、处理错误并检查结果。这套系统常被称为 Agent Harness。

例如一个编程 Agent 接到修改需求后，需要读取仓库规则、定位文件、修改内容、运行验证、记录进度，再向用户交付。模型每轮看到什么、可以做什么、上轮执行到了哪里，都由运行系统组织。因此，同一模型配合不同的上下文和执行机制，也会表现出不同的任务完成效果。

哪些系统能力会影响结果？

能力 作用
持久规则与记忆 保留项目约定、用户纠偏和长期有效信息，减少重复摸索
上下文组织 按需加载相关文件和工具结果，压缩历史时保留任务状态
工具设计 把输入、输出、错误和成功条件说明清楚，使模型容易选对并用好工具
执行与恢复 管理超时、重试、检查点和中断恢复，让长任务可以接续
权限与任务分工 按任务开放操作范围，把独立工作交给子 Agent，汇总其结果
评测与反馈 记录执行轨迹，用真实失败案例改进工具、上下文和流程

长任务尤其需要明确“已经完成什么，下一步做什么”。例如初始化阶段写好任务清单，执行阶段每次完成一个可验证的部分，保存进度和测试结果，下一轮就能在已有工作上继续。

多轮工具调用应该保留什么状态？

原笔记讨论了如何把研究任务里的语义引导迁移到更通用的 Agent。这里的“语义引导”就是明确告诉压缩器：下一步决策最需要哪些信息。可以分成四层：

  1. 任务目标与约束。 当前要交付什么，有哪些时间、预算、格式和授权要求。
  2. 当前事实与待解决问题。 哪些信息已经确认，哪些是假设，哪些发生冲突或仍需验证。
  3. 本次工具调用意图。 这一步要回答什么问题、读取哪个字段，或改变哪个外部对象。
  4. 执行后的状态更新。 提取新事实、变更结果、待办和异常，并带上来源与时间。

研究任务适合用覆盖清单；故障排查可以组织成待验证假设；审批任务可以保存流程节点；会修改外部系统的任务需要保存对象状态和操作记录。根据任务结构选择状态表示，压缩时才能保住有用的信息。

用一个多轮操作例子说明

假设 Agent 要查询订单物流，并在用户要求的条件下修改收货地址。它首先保存订单号、目标地址、允许修改的条件；查询物流后记录发货状态和更新时间；调用修改工具前确认当前步骤允许操作；执行后保存新的地址、返回的操作编号和结果。

这份状态中有三个特别有用的信息：

  • 操作回执（action receipt）：记录已经执行的修改、对象 ID 和返回状态。中断后可以查询执行结果，再决定是否重试。
  • 来源（provenance）与时效（freshness）：记录事实来自哪个工具、何时取得。继续行动前，按业务要求刷新会变化的字段。
  • 意外信息缓冲区：保留当前状态表里尚无位置、却可能改变计划的新信息，例如订单已经拆成两单。后续判断其影响，再更新状态结构。

摘要应优先保留这些决策信息。大量重复说明、过期工具输出和与当前步骤无关的细节可以移到外部记录，需要时再取回。

怎样确认优化有效？

固定模型和任务集，分别调整上下文策略、工具描述、恢复机制或子任务分工，观察任务完成率、错误类型、重试次数、总 token、时延和费用。

例如，如果问题集中在重复修改外部对象，就检查回执保存与恢复逻辑；如果集中在忘记任务约束，就检查状态表示和压缩；如果集中在工具选错，就检查工具可发现性和接口说明。这样能把“Agent 效果提升”落实到可解释、可迭代的系统机制。
