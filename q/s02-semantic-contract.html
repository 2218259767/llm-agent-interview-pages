结构化输出、语义正确性与执行权限为什么要分开？

重点复习频率待统计约 2 分钟
更新于 2026-10-13·Agent 算法 / Agent 研发 / 大模型算法

题目

结构化输出、语义正确性与执行权限为什么要分开？

SPEAK WITH CLARITY · 面试表达

面试口述回答

我会把输出格式、判断语义和执行授权拆成三层。schema 只能保证答案长得合法，不能保证选得对；模型说允许，也不能代替用户权限和业务状态校验。比如取消订单，编号类型正确仍可能是错单、已发货或越权，所以执行端要重新验证归属和状态，并做幂等控制。我也会给证据不足和系统失败留明确分支，避免把所有请求强迫塞进一个合法但错误的选项。

详细知识笔记展开 / 收起

三层责任

结构层检查 JSON 是否能解析、字段类型、枚举、必填项与约束；语义层判断标签和参数是否符合用户意图与证据；执行层核对主体权限、目标对象、当前状态和幂等条件。模型输出的 allow 标签只是一项判断结果，不是授权令牌。

在五个候选里只能返回一个合法编号，不代表五个里面存在正确答案。应区分“其他类别”“证据不足”“需要澄清”“系统失败”，避免把不同状态挤进一个兜底标签。

例子

模型产生符合 schema 的订单取消请求，仍可能取消错订单，或者订单已发货、调用者没有权限。执行服务应重新校验用户与订单归属、订单版本及允许的状态迁移。模型看见旧数据后到真正执行前状态可能变化，校验要尽量靠近提交。

失败处理

解析失败走修复或拒绝分支；证据缺失先补材料或澄清；权限不满足不让模型反复改参数重试。工具返回的外部文本是数据，不能升级成执行策略。安全与可靠性评估应同时覆盖合法格式的错误内容、恶意材料和并发状态变化。

仅凭服务返回固定 JSON 形状，不能推断内部一定采用某种 token masking 算法。接口契约、实现机制与端到端正确性是三个不同证据层次。
