什么是 LoRA 和 QLoRA？

约 20 分钟
更新于 2026-11-03

题目

请介绍 LoRA 和 QLoRA 的原理，并说明它们与全参数微调的区别。

面试口述回答

首先，LoRA 要解决的就是大模型中如何不做全参数微调，就能够高效地适配一个垂直场景，或者说适配一个下游任务的问题。因为全参数微调的一个主要成本在于显存占用非常高。我们在训练模型的时候，梯度和优化器状态会带来很大的显存开销，此外还有模型权重和激活值等占用。

LoRA 的做法是：假设一个参数矩阵为 WWW，它的尺寸是 (d,k)(d,k)(d,k)，如果做全参数微调，那么就会有 d×kd\times kd×k 个元素都要计算梯度、维护优化器状态。在 LoRA 中，我们将 W0W_0W0​，也就是初始权重冻结，另外训练 BBB 和 AAA 两个矩阵，用它们的乘积表示低秩增量。其中 BBB 的尺寸是 (d,r)(d,r)(d,r)，AAA 的尺寸是 (r,k)(r,k)(r,k)。这个参数 rrr 就是 LoRA 的秩。rrr 越大，在 LoRA 训练中，它的拟合能力越强，相对来说过拟合的风险也可能更高。

加上缩放系数后：

W=W0+ΔW=W0+αrBA.W=W_0+\Delta W=W_0+\frac{\alpha}{r}BA.W=W0​+ΔW=W0​+rα​BA.

这个参数 α\alphaα 也是一个超参数，通常会将 α/r\alpha/rα/r 设置为一个固定比值。在训练的过程中，只有 BBB 和 AAA 这两个小矩阵需要计算参数梯度、更新参数，这样一来，梯度和优化器状态的显存占用就会大幅降低。因为在工程实践中，这个 rrr 是一个非常小的数。另外，使用 LoRA 而不使用全参数微调，也可能有缓解过拟合的效果。

再说回 AAA、BBB 这两个矩阵。将 AAA 矩阵高斯初始化，将 BBB 矩阵全零初始化。这样在刚开始训练的时候，BBB 和 AAA 的乘积就是一个全零矩阵，保证一开始的输出和微调之前的模型输出保持一致，避免随机初始化的旁路在一开始干扰原模型的输出。

说完了 LoRA，我们再说 QLoRA。QLoRA 是在 LoRA 的基础上，对基座模型做了进一步量化。对于 LoRA 来讲，我们使用的基座模型一般是 FP16 或者 BF16 的。而 QLoRA 则是进一步将基座模型量化到 4-bit，并且在训练的时候使用了分页优化器和双重量化。

LoRA：冻结原权重，只训练低秩增量

LoRA（Low-Rank Adaptation，低秩适配）是一种参数高效微调方法。全参数微调会更新模型原来的全部权重；LoRA 冻结预训练权重，用两个小矩阵学习任务需要的权重变化。其出发点是：下游任务所需的有效更新可以具有较低的秩。

对于原权重 W0∈Rd×kW_0\in\mathbb R^{d\times k}W0​∈Rd×k，LoRA 的前向计算是：

h=W0x+αrBAx,h=W_0x+\frac{\alpha}{r}BAx,h=W0​x+rα​BAx,

其中 A∈Rr×kA\in\mathbb R^{r\times k}A∈Rr×k 先降维，B∈Rd×rB\in\mathbb R^{d\times r}B∈Rd×r 再升维；rrr 是秩，α/r\alpha/rα/r 控制增量分支的幅度。可训练参数由 dkdkdk 降为 r(k+d)r(k+d)r(k+d)。例如 d=k=4096,r=8d=k=4096,r=8d=k=4096,r=8 时，一个线性层的可训练参数从约 1678 万降到约 6.6 万。

原始 LoRA 用随机初始化的 AAA 和全零的 BBB，让初始 BA=0BA=0BA=0，从预训练模型的原始输出开始学习。训练第一步先产生 BBB 的梯度，随后两个矩阵一起更新。

LoRA 节省了什么，怎样选择配置

冻结原权重后，主要减少的是基座参数对应的梯度和优化器状态，以及每个任务需要保存的适配器体积。基座权重和训练激活仍占显存。部署单个适配器时，可以先合并 W=W0+αBA/rW=W_0+\alpha BA/rW=W0​+αBA/r，继续使用原线性层；多适配器动态切换时，则由服务框架管理额外分支和批处理。

Rank、Alpha 和目标层分别控制什么？

Rank 控制增量的表达容量。AAA 把输入压到 rrr 维，BBB 再把它映射回输出空间。增大 rrr，可学习的更新方向更多，同时可训练参数、梯度和优化器状态也按 r(k+d)r(k+d)r(k+d) 增加。可以从 8、16、32、64 等候选出发，用任务表现确定需要多大容量。

原笔记提出的追问是：为什么 Rank 选得太大，效果反而可能变差？一个具体场景是，只有少量同一风格的训练样本，却用了很大的秩和较多训练轮数。较强的拟合能力会让模型更容易记住措辞、模板和样本噪声：训练损失继续下降，换一批表达方式后的验证表现却下降。此时应结合数据量、训练轮数和验证曲线选择容量。若小秩模型在训练集和验证集上都学不好，再考虑增加秩或扩大适配层的范围。

Alpha 控制增量分支的幅度。原始 LoRA 使用 α/r\alpha/rα/r 缩放 BAxBAxBAx：在相同的 AAA、BBB 下，缩放越大，旁路对输出的影响越大。它与学习率一起影响训练，但分别作用于前向分支幅度和参数更新步长。比较不同秩时，要同时记录 α\alphaα 和 α/r\alpha/rα/r，这样才能分清效果变化来自容量还是缩放。

目标层决定在哪些模块适配。只给 Q、V 投影加 LoRA，可以用较小代价改变注意力中的信息选择与表示；把其他注意力投影和 MLP 线性层也纳入，可以扩大可调整的功能范围。实践中可以先确定要覆盖的模块，再比较不同秩，而不是只盯着一个 rrr 数值。

LoRA 与全参数微调，怎样按场景选择？

原笔记把任务分成了两类：一类是在基座已有能力上做指令、风格和格式适配；另一类是领域跨度大、需要学习较多新内容的适配。这个区分的价值，是把“模型要改变什么”与“允许多大的参数更新空间”联系起来。

场景 可以先尝试的方案 为什么这样选
指令遵循、回复风格、JSON 或工具参数格式 LoRA 基座已有语言与任务知识，主要学习怎样组织输出，低秩更新通常是成本较低的起点
多个客户或业务各有不同风格、术语与格式 共用基座，分别训练 Adapter 每个任务只保存小型增量，版本管理与切换更方便
新领域与基座差异较大，且有充足高质量数据和算力 比较扩大目标层的 LoRA 与全参数微调 全参允许各层权重在更大的空间中调整；同时要监控领域收益和通用能力变化
数据量少、格式重复较多 较小秩与较短训练作为起点 先控制容量与训练强度，用独立验证集检查是否学到了可泛化的规则

例如把通用模型适配成固定格式的客服助手，主要变化可能是语气、字段顺序与回答流程，LoRA 很适合作为第一版。若任务涉及大量基座不熟悉的专业表达和知识，则需要同时考虑数据覆盖、继续预训练或领域微调的训练方式，再比较低秩更新与全参更新的效果。选型顺序可以概括为：先看任务变化和数据，再看参数容量，最后结合显存与训练周期决定方案。

QLoRA：进一步压缩冻结的基座

QLoRA 将冻结的基座权重以 4-bit 量化形式保存，再训练较高精度的 LoRA 参数。计算时按需反量化参与矩阵运算，梯度通过计算图传到 LoRA 分支。其关键设计包括：

  1. NF4：针对近似正态分布权重设计的 4-bit 表示。
  2. 双重量化：继续量化量化过程中的缩放常数，节省元数据存储。
  3. 分页优化器：利用 CPU/GPU 内存管理缓解训练时的显存峰值。

因此，LoRA 主要压缩“需要更新的参数”，QLoRA 进一步压缩“必须加载的基座权重”。选择时先估算基座、激活、优化器和最长样本的显存需求：显存宽裕时可用 BF16 基座加 LoRA，显存受限时可评估 QLoRA，再用同一验证集比较质量和吞吐。

补充阅读

一、从数学角度看，LoRA 为什么有效？

可以先抓住两个层次：预训练已经提供了大量能力；适配下游任务所需的有效变化，可能集中在较少的方向上。

“低内在维度”研究发现，在其测试的一些任务中，即使只在整个参数空间的较小子空间里优化，也能接近全参数微调的表现。这为参数高效微调提供了依据。这里的“参数空间自由度”和“单层矩阵的秩”是不同概念，前者给后者提供研究动机。低内在维度原论文

从矩阵角度，假设某个任务理想的权重增量是 ΔW∗\Delta W^*ΔW∗，对它做奇异值分解：

ΔW∗=UΣV⊤=∑iσiuivi⊤.\Delta W^*=U\Sigma V^\top=\sum_i \sigma_i u_i v_i^\top.ΔW∗=UΣV⊤=i∑​σi​ui​vi⊤​.

可以把每一项理解为：沿某个输入方向提取信息，再沿相应的输出方向作修正。奇异值 σi\sigma_iσi​ 描述该项在矩阵变化中的大小。

如果主要变化集中在前 rrr 项，保留它们就能得到较好的近似：

ΔWr=UrΣrVr⊤=BA.\Delta W_r=U_r\Sigma_rV_r^\top=BA.ΔWr​=Ur​Σr​Vr⊤​=BA.

例如取 B=UrΣrB=U_r\Sigma_rB=Ur​Σr​、A=Vr⊤A=V_r^\topA=Vr⊤​。Eckart–Young 定理说明，秩不超过 rrr 的最优近似，其平方误差为：

min⁡rank⁡(X)≤r∥ΔW∗−X∥F2=∑i>rσi2.\min_{\operatorname{rank}(X)\le r}\|\Delta W^*-X\|_F^2=\sum_{i>r}\sigma_i^2.rank(X)≤rmin​∥ΔW∗−X∥F2​=i>r∑​σi2​.

尾部奇异值越小，舍去这些方向带来的矩阵误差就越小。 这解释了低秩表示在什么条件下可以保留主要变化。MIT 线性代数讲义，定理 2.1.2

再看实际前向计算：

Δh=BAx=∑i=1rbi(ai⊤x).\Delta h=BAx=\sum_{i=1}^{r}b_i(a_i^\top x).Δh=BAx=i=1∑r​bi​(ai⊤​x).

这意味着：

  • AAA 从输入中提取少量与任务相关的组合。
  • BBB 把这些组合转换成输出修正。
  • 原有的 W0xW_0xW0​x 完整保留，多层适配器还可以通过网络的非线性共同作用。

所以，LoRA 可以用较少参数调整已有能力的使用方式。低秩限制作用于增量，各层的原有能力仍然保留。

实际训练时，LoRA 直接优化 AAA、BBB，并不先完成全参微调再做 SVD。LoRA 原论文在所测任务上验证了小秩更新的有效性；具体需要多大的秩，仍取决于任务、基座和适配位置。上面的 SVD 推导解释的是“为什么可能存在好的低秩近似”，任务效果则需要实验验证。LoRA 原论文 v2，§4、§7

x=(−1)s(1+F2m)2E−bias.x=(-1)^s\left(1+\frac{F}{2^m}\right)2^{E-\mathrm{bias}}.x=(−1)s(1+2mF​)2E−bias.

符号位决定正负，指数决定量级，小数部分决定数字能刻画得多细。

FP16 把更多位数给了精细程度，BF16 把更多位数给了量程。

看两个具体例子：

  • 精细程度：从 1 往上，FP16 相邻数间隔为 2−10=0.00097656252^{-10}=0.00097656252−10=0.0009765625，BF16 为 2−7=0.00781252^{-7}=0.00781252−7=0.0078125。按最近舍入，1.001 存成 FP16 约为 1.0009765625，存成 BF16 则为 1。
  • 量程：100000 超过 FP16 最大有限值 65504，而 BF16 可以近似表示它。

因此，同样占两个字节，FP16 能在较窄范围里区分更细的数，BF16 能容纳跨度更大的数。

训练时，FP16 常配合 loss scaling 保护较小的梯度；BF16 的宽指数范围通常减少了这项需求。与此同时，关键累加或优化器状态仍可以使用 FP32。例如 Google TPU 官方说明采用 BF16 乘法、FP32 累加。NVIDIA 混合精度指南、Google TPU 官方说明

三、7B 模型做全参、LoRA、QLoRA，显存怎么算？

先分清两笔账：

训练峰值显存=模型状态+激活、工作区和运行时等开销.\text{训练峰值显存}=\text{模型状态}+\text{激活、工作区和运行时等开销}.训练峰值显存=模型状态+激活、工作区和运行时等开销.

模型状态包括权重、梯度、优化器状态，以及某些混精方案中的 FP32 主权重。激活则受 micro-batch、序列长度、重计算和注意力实现影响。HF 官方显存构成说明

我们选一组明确的教学配置：

  • 总参数 P=7×109P=7\times10^9P=7×109，按约 7B 算账。
  • micro-batch 为 1，上下文 2048，梯度累积 16，开启高效注意力和逐层激活重计算。
  • 无 ZeRO/FSDP 分片、无 CPU offload。
  • LoRA 取 rank 16，加入注意力和 FFN 的七个投影。按 32 层、hidden 4096、FFN intermediate 11008 的结构估算，适配器参数 TTT 约为 4000 万。
  • 下文用 GiB，即 2302^{30}230 字节；GB 则是 10910^9109 字节。

先算模型状态。

全参采用本例指定的混精 Adam 方案：

状态 每参数字节数

BF16 梯度 2

所以：

Mfull,state=16P=112 GB≈104.3 GiB.M_{\mathrm{full,state}}=16P=112\ \mathrm{GB}\approx104.3\ \mathrm{GiB}.Mfull,state​=16P=112 GB≈104.3 GiB.

LoRA 冻结基座，只给适配器维护训练状态。本例适配器使用 FP32 参数、FP32 梯度和两个 FP32 Adam 状态，同样共 16T16T16T 字节：

MLoRA,state=2P+16T≈13.6 GiB.M_{\mathrm{LoRA,state}}=2P+16T\approx13.6\ \mathrm{GiB}.MLoRA,state​=2P+16T≈13.6 GiB.

其中约 13.04 GiB 是基座权重，0.60 GiB 是适配器训练状态。

QLoRA 则进一步量化基座。考虑双重量化元数据后，每个量化参数约占 4.127 bit；同时，Embedding、LM head、Norm 等部分保留较高精度。本例将这部分设为约 0.2624B 参数，因此：

这里 PqP_qPq​ 是量化参数量，PhiP_{\mathrm{hi}}Phi​ 是保留 BF16 的基座参数量。4.127 的来由在第四问展开。QLoRA 原论文 §2–3

然后加上激活和临时开销。

四、分页优化器和双重量化分别做了什么？

先讲分页优化器。

Adam 要为可训练参数维护一阶、二阶统计量，也就是通常说的 mmm、vvv。Paged Optimizer 使用 CUDA Unified Memory，使相应状态可以在 CPU 内存与 GPU 显存之间按页迁移。

当训练出现较大的临时显存需求时，部分状态页可以移到 CPU；后续需要访问时再迁回或预取，从而缓解 GPU 的峰值压力。QLoRA 中，这些优化器状态主要属于可训练的适配器。bitsandbytes v0.48.1 官方说明

可以这样记：

分页决定状态放在哪里；8-bit、32-bit 决定状态怎样表示。

所以分页优化器也可以保存 FP32 状态。状态仍占总内存，发生迁移时还会付出 CPU/GPU 传输代价。官方实现

再讲双重量化。

第一次量化一般按块处理权重。例如，每 64 个权重共用一个缩放量 sss，可以直观写成：

wi≈s qi.w_i\approx s\,q_i.wi​≈sqi​.

权重编码占 4-bit，缩放量若用 FP32 保存，还需要额外空间。每 64 个权重存一个 32-bit 缩放量，平均每参数增加：

3264=0.5 bit.\frac{32}{64}=0.5\ \text{bit}.6432​=0.5 bit.

所以，算上这层元数据，实际约为 4.5 bit/参数。

Double Quantization 的做法是：把这些缩放量再量化一次。

原论文对缩放量去均值后，用 8-bit 保存，并为每 256 个缩放量保留一个第二级 FP32 缩放常数。这样，平均元数据开销变成：

864+3264×256≈0.127 bit/参数.\frac{8}{64}+\frac{32}{64\times256}\approx0.127\ \text{bit/参数}.648​+64×25632​≈0.127 bit/参数.

于是总量从约 4.5 bit 降到 4.127 bit，每个量化参数节省约 0.373 bit。在前面的算例里，这一项额外节省约 0.31 GB。QLoRA 原论文，Double Quantization

这里两次量化的对象依次是：权重、第一次量化所需的缩放常数。

最后联系第二问：QLoRA 的低位格式主要用于保存基座，矩阵计算时按需反量化到 BF16 等计算精度，适配器继续以较高精度训练。因此，双重量化减少的是存储元数据，分页优化器管理的是状态驻留位置。作者与 HF 的原始集成说明
