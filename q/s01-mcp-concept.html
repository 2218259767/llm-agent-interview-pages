MCP 是什么？它和 Function Calling 有什么关系？

约 4 分钟
更新于 2026-10-13

题目

MCP 是什么？它和 Function Calling 有什么关系？

面试口述回答

MCP 是模型上下文协议，用来标准化 Agent 应用与外部工具、数据源的通信。它的结构分成 Host、Client 和 Server：Host 负责模型与工作流，Client 负责协议通信，Server 暴露工具、资源和提示模板。它和 Function Calling 很适合配合使用：先通过 MCP 发现工具，把工具定义交给模型，模型选择工具并生成参数后，再通过 MCP 执行并取回结果。我认为它的主要价值是把工具接入做成可复用的接口，让 Agent 的规划逻辑和具体业务工具可以分别维护，接入新能力时更省适配成本。

详细知识笔记展开 / 收起

定义：Agent 接入工具和数据的标准协议

MCP（Model Context Protocol，模型上下文协议）规定 AI 应用与外部工具、数据源之间如何通信。它用统一的能力描述和调用接口，让工具提供方与 Agent 应用能够独立开发、复用和组合。可以把它理解为 AI 应用接入外部能力的标准接口。

Host、Client、Server 分别负责什么？

角色 职责 例子
Host 承载模型交互、上下文和 Agent 工作流，管理多个 Client 一个 AI 桌面应用或编码 Agent
Client 在 Host 内与某个 Server 通信 连接企业知识库服务的协议组件
Server 暴露具体工具、资源和提示模板 数据库查询服务、文件服务

Host 可以接入多个 Server，每条连接由对应 Client 管理。Server 可在本机运行，也可部署为远程服务。

三类核心能力

  • Tools：可执行的操作，如搜索文档、查询数据库、创建工单。
  • Resources：可读取的上下文数据，如文件内容、数据库结构。
  • Prompts：可复用的交互模板，如代码审查或故障排查模板。

工具通过标准 schema 描述名称、作用与参数。Client 可用 tools/list 获取工具列表，再用 tools/call 发起调用；这降低了应用接入不同工具时的重复适配工作。

与 Function Calling 怎样配合？

Function Calling 描述模型根据工具定义选择工具、生成结构化参数的能力；MCP 为应用提供工具发现和远端执行接口。一条典型链路是：

  1. Host 通过 MCP Client 获取 Server 的工具描述。
  2. Host 将适合当前任务的工具定义提供给模型。
  3. 模型生成工具名与参数。
  4. Host 校验参数和授权，通过 Client 发起 tools/call。
  5. Server 执行并返回结果，Host 将结果加入上下文，模型继续处理任务。

接入价值与工程分工

统一协议让同一个 Server 能服务多个 AI 应用，也方便跨语言、跨机器使用工具。工具服务维护业务 API、凭证和执行逻辑，Host 维护规划、上下文和调用策略；两端共同落实权限校验、超时、日志与错误处理。

在 2026-07-28 协议中，可通过 server/discover 获取版本与能力，每个请求携带相关协议元数据；本地常用 stdio，远程常用 Streamable HTTP。
