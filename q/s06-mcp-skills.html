Agent／工具调用、MCP 与 Skills

Skills 与 MCP 有什么区别，为什么不把所有流程写进 System Prompt？

频率待统计样本见于 1 场约 4 分钟
更新于 2026-10-13·Agent 算法 / Agent 研发 / 大模型算法
常见问法 · 2
  • MCP 与 Skills 区别
  • 工具协议与任务工作流

题目

Skills 怎样封装任务知识，与 MCP 怎样配合？复杂流程如何拆分，脚本执行与加载成本如何管理？

SPEAK WITH CLARITY · 面试表达

面试口述回答

Skill 主要解决任务知识的复用和按需加载，MCP 主要解决外部能力的接入。做研究报告时，Skill 规定核验、组织与验收步骤，MCP 可以接入检索服务。相比把所有流程塞进 System Prompt，Skill 能减少无关上下文并独立维护，但也引入了路由漏选和依赖加载的问题。我会把入口写短，复杂参考与脚本分开，并用触发准确率、任务成功率和总成本验证收益。脚本让确定性步骤可重复执行，但权限仍由宿主控制，不能因为一个 Skill 写了某项操作就直接获得执行资格。

详细知识笔记展开 / 收起

职责与组合

MCP 规定应用怎样接入外部工具与上下文服务，Skill 则封装完成某类任务的操作知识。模型仍需通过工具调用提出执行请求，宿主负责执行和权限控制；Skill 文件本身不产生新权限。MCP 与 Function Calling 的协议边界另有专题题目，本题重点是知识组织与流程复用。

Skill 是可按需载入的操作知识包，以 SKILL.md 描述任务触发条件与步骤，也可带脚本、参考资料和模板。它告诉 Agent 如何完成一类任务；发现时先读简短元信息，匹配后再读完整说明，有助于控制上下文占用。

为什么不全部写进 System Prompt

把大量任务说明常驻上下文，会增加无关信息、维护冲突和检索负担。按需加载能让多个任务知识包独立版本化，并只在匹配时加入详细步骤；代价是发现与路由可能漏掉正确 Skill，或者选入错误 Skill。因此它是模块化与加载策略，不是让模型获得某种必然更强的推理能力。

SKILL.md 的 YAML 元信息描述名称与适用任务，正文放核心步骤；长参考材料放 references/，可执行程序放 scripts/，模板资源放 assets/。复杂流程要有入口、分支条件、失败处理与验收标准，不应让入口文件继续无限膨胀。脚本适合承接确定性计算，但运行前仍要满足依赖、输入校验与宿主权限要求。

组合与验证

一个报告制作 Skill 规定先核对数据口径，再画图并验收；它可以调用经 MCP 接入的查询工具。模型用结构化工具调用提出参数，Host 检查范围并执行。三者可以组合，也可以各自独立使用。

我会分别衡量触发准确率、是否漏加载必要参考、任务成功率、额外 token 与脚本失败率，并比较小规模固定提示词基线。对简短、固定、频繁必需的规则，常驻提示词可能更直接；按需加载不是任何场景都更省成本。

面试加分的边界

接通协议不等于工具选择准确，加载 Skill 不等于流程必然成功。需要验证发现/路由、参数语义、权限、超时、重试与结果校验。外部说明与工具结果不能自行扩大执行系统的权限。
