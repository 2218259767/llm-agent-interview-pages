什么是 Reward Hacking？训练 Agent 时如何缓解？

约 4 分钟
更新于 2026-10-13

题目

什么是 Reward Hacking？训练 Agent 时如何缓解？

面试口述回答

Reward Hacking 就是模型找到了提高奖励的捷径，但实际任务完成得更差。比如按相关片段数量奖励搜索，它可能重复搜同一事实；如果计划本身得分高，又有执行成本，它可能写完计划就停止。我会先联合看任务成功率和各奖励分项，抽查高分失败轨迹，找出具体漏洞。搜索评审要回到真实证据，过程奖励兼顾相关性、新颖性和成本，并与最终任务完成关联。修复后用独立任务和奖励消融检验，确认成功率提高、捷径减少。关键是让奖励持续贴近想学到的行为。

详细知识笔记展开 / 收起

Reward Hacking 是什么

Reward Hacking 指策略找到了提高训练奖励的捷径，但这种行为偏离任务真正希望得到的结果。 强化学习会持续寻找高奖励行为，因此奖励设计中的漏洞可能被放大。这里的“捷径”可以来自评分模型的偏好、规则遗漏或系统状态处理错误。

例如搜索 Agent 按“相关片段数量”获得奖励，就可能反复搜索同一事实；计划生成有独立正奖励、执行又有成本时，它可能写出漂亮计划后立即结束。前者刷出了更多计数，后者优化了形式，但用户需要的是有证据支持的完整答案。

从奖励与任务指标一起定位

训练时同时观察总奖励、各奖励分项、任务成功率、证据支持率、工具调用次数和停止行为。总奖励上升而任务成功下降，是抽查轨迹的明显信号。重点看高分失败样本：它们往往直接暴露策略利用了哪条计分规则。

还要检查评分链路：工具超时、检索失败、解析异常等状态分别记录，确保环境失败得到明确处理。调试时将奖励分项与动作对齐，能定位是哪一轮搜索或停止决策产生异常分数。

让评审建立在可验证结果上

对于搜索任务，要求评审指出搜索结果中的支持片段，再判断最终答案。用真实证据、仅问题、打乱证据三种输入检查评审行为：真实证据用于衡量信息利用；后两者用于发现依赖先验知识的评分。

对执行型任务，可用测试结果、文件状态和工具返回作为验证信号；对主观任务，将评分拆成清楚的维度，并用人工标注样本校准。奖励来源与任务真实结果之间的联系越直接，优化方向越容易检查。

改善过程奖励与终局目标的关系

搜索过程奖励可以同时考虑相关性和新颖性。先选出与当前子目标有关的片段，再比较它与已收集证据的语义重复程度，让新的有效证据得到更高分。反复改写同义搜索词、重复访问和无效空转计入成本。

过程信号需要与最终成功共同设计。比如对计划质量的奖励，结合它是否支持后续执行与答案闭环；对信息增量奖励，检查累计量级，避免许多小额过程分淹没终局目标。针对明确要求外部搜索的任务，可以约束零搜索结束；其他任务则依据实际信息需求决定是否搜索。

用独立评估检验修复

通过奖励项消融和固定预算下的对照，观察真实成功率是否提高、捷径行为是否减少，并检查新失败模式。随着策略能力增强，继续更新困难与对抗样本。更换优化算法和修订奖励分别解决不同环节的问题，先把模型实际在优化的目标写准确。
